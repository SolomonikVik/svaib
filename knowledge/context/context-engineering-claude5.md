# Context Engineering для моделей поколения Claude 5

## Кратко

Смена парадигмы context engineering при переходе на модели поколения Claude 5: инструкции, которые раньше повышали качество, теперь его снижают. Anthropic удалила **более 80% системного промпта Claude Code** для продвинутых моделей поколения — без измеримой потери на coding-евалах. Вместо жёстких правил модель опирается на окружающий контекст и собственное суждение; вместо монолитного набора инструкций — послойная выдача (progressive disclosure) через скиллы и отложенную загрузку инструментов. Автор термина «unhobbling Claude» — Thariq Shihipar, инженер Anthropic (июль 2026).

Практический смысл: набор инструкций, накопленный под предыдущие поколения моделей, нужно не дополнять, а **сокращать** — это отдельная инженерная работа, которая делается при смене поколения.

## Почему старые промпты вредят

Три диагноза из разбора системного промпта Claude Code:

- **Конфликтующие сигналы.** «Оставляй документацию где уместно» рядом с «НЕ ДОБАВЛЯЙ комментарии». Каждая инструкция писалась под свой случай, вместе они противоречат друг другу, и модель тратит способность на разрешение конфликта.
- **Избыточная спецификация.** Ограничения, когда-то необходимые для безопасности и предсказуемости, на более способной модели становятся контрпродуктивными: сужают пространство решений там, где модель нашла бы лучший вариант.
- **Перегруз инструментов.** CLAUDE.md исторически нёс на себе роль памяти. Когда появились авто-память, артефакты и скиллы, эта нагрузка стала дублированием.

## Шесть сдвигов

| Было | Стало |
|---|---|
| Давать правила | Давать судить самому |
| Давать примеры | Проектировать интерфейсы |
| Класть всё upfront | Progressive disclosure |
| Повторять важное | Одно простое описание инструмента |
| Память в CLAUDE.md | Авто-память |
| Простые спеки | Богатые референсы |

**1. Правила → суждение.** Показательная замена в системном промпте Claude Code: вместо «по умолчанию не пиши комментарии, никогда не пиши многоабзацные докстринги» — «пиши код, который читается как окружающий: совпадай по плотности комментариев, именованию, идиоме». Одна фраза про намерение вместо перечня запретов.

**2. Примеры → интерфейсы.** Примеры в промпте сужают пространство исследования — модель тяготеет воспроизводить показанное. Более сильный рычаг — выразительные параметры инструментов: enum-значения сами подсказывают допустимое использование, и подсказка живёт в схеме, а не в тексте промпта.

**3. Всё upfront → progressive disclosure.** Детальные инструкции выносятся в отдельные скиллы (например, процедура верификации — в собственный скилл вместо блока в системном промпте). Инструменты грузят полные определения только когда понадобились — механика отложенных инструментов и поиска по ним.

**4. Повторы → простые описания.** Одна и та же мысль, продублированная в системном промпте и в описании инструмента, работает против себя. Руководство по использованию — прямо в описание инструмента, дубли — удалить.

**5. CLAUDE.md как память → авто-память.** Ручное сохранение фактов по хоткею устарело: модель сама сохраняет релевантное. CLAUDE.md остаётся, но с другой ролью (ниже).

**6. Простые спеки → богатые референсы.** Markdown-план — не единственный носитель спецификации. Работают HTML-артефакты, ссылки на код, тест-сьюты как спека, рубрики для агентов-верификаторов. Ключевая формулировка источника: **HTML-мокап обычно даёт лучший результат, чем описание или скриншот** — код как референс богаче прозы.

## Архитектура сборки контекста

Четыре слоя, у каждого своя роль. Смысл разделения в том, чтобы содержимое не мигрировало между слоями и не дублировалось.

| Слой | Роль | Правило |
|---|---|---|
| **System prompt** | Привязан к продукту: в каком продукте работает модель | Пользователь его почти не меняет |
| **CLAUDE.md** | Краткое описание репозитория + **грабли** кодовой базы | Не писать очевидное, что модель прочитает из файловой системы. Пример полезного: «типы лежат в одном монолитном файле» |
| **Skills** | Лёгкие проводники к информации, командные и продуктовые мнения, best practices | Не переограничивать, кроме критичных зон. Длинный скилл — дробить на несколько файлов |
| **References (@mentions)** | Глубокое содержание задачи: спеки, мокапы, код | Предпочитать код описанию |

## Границы: чего сдвиг не отменяет

Наблюдение при сверке с официальным руководством по промптингу поколения (→ [../prompting/claude-5-prompting.md](../prompting/claude-5-prompting.md)): «меньше инструкций» — не то же самое, что «никаких инструкций». Само руководство состоит из готовых инструкций-врезок. Меняется их **характер**, а не наличие:

- Исчезают перечни частных запретов («не делай A, не делай B, не делай C»).
- Остаются короткие декларации намерения и границ («когда информации достаточно — действуй», «пауза только там, где нужен человек»).
- Остаются жёсткие правила там, где цена ошибки высока и шаг хрупкий, — это совпадает с принципом «степеней свободы» в проектировании скиллов (→ [../skills/!skills.md](../skills/!skills.md)).

## Инструмент ревизии

Команда `/doctor` в Claude Code — автоматическая помощь в «rightsize» скиллов и файлов CLAUDE.md: подсказывает, что стало избыточным. Первый практический шаг при миграции существующей конфигурации на новое поколение моделей.

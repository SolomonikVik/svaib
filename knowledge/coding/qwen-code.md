# Qwen Code

## Кратко

Qwen Code — открытый харнесс с расширениями, агентными профилями, command-хуками, MCP и ACP. Его установщик умеет импортировать Claude-пакеты, но перенос ресурсов не гарантирует сохранение всех деклараций и поведения. Совместимость Python-хуков зависит от событий, имён инструментов, полезной нагрузки и формы ответа обработчика.

## Импорт и обнаружение

Конвертация Claude-плагина создаёт представление расширения Qwen. Скиллы и агентные профили обнаруживаются своими загрузчиками; оставшийся в каталоге исходный файл конфигурации может не стать активной настройкой. Особенно важно проверить MCP: физическое наличие `.mcp.json` после конвертации не доказывает, что сервер зарегистрирован. См. [репозиторий и документацию](https://github.com/QwenLM/qwen-code) и [настройки](https://github.com/QwenLM/qwen-code/blob/main/docs/users/configuration/settings.md).

Профиль дочернего агента нужно проверять не только по записи в каталоге. Исполнение подтверждается отдельной сессией, доступными инструментами и результатом задания. ACP даёт оболочке протокол общения с харнессом; он не переносит установку плагинов в саму оболочку. См. [BB](../tools/bb.md).

## Command-хуки

Qwen может запускать Python как command-хук. Перед диагностикой нужно проверить разрешение на исполнение и фактический запуск команды. Нормализовать приходится и matcher, и данные события: native `write_file`, `read_file`, `edit` и `run_shell_command` могут отличаться от имён, ожидаемых Claude-обработчиком. Перевод только matcher не меняет `tool_name`, который получает скрипт.

Контекст из хука должен попасть в запрос модели; отказ — остановить native инструмент до изменения файла. Нулевой exit code подтверждает только завершение процесса. Для Stop нужно учитывать последнее сообщение события, структуру журнала и `stop_hook_active`; простое чтение строк с Claude-полем `type: assistant` не является универсальным интерфейсом. Подробности переноса — в [контрактах хуков](../plugins/cross-harness-hooks.md).

## Контекст и фоновая память

Настройки модели позволяют объявить реальное окно контекста и параметры генерации. Для OpenAI-совместимых провайдеров лимит выхода задаётся через `model.generationConfig.samplingParams.max_tokens`, а окно — через `model.generationConfig.contextWindowSize`; при конфигурации именованного model provider нужно учитывать его собственные generation settings. См. [конфигурацию](https://github.com/QwenLM/qwen-code/blob/main/docs/users/configuration/settings.md).

У Qwen есть фоновая извлекаемая память и её консолидация. `memory.enableManagedAutoMemory=false` выключает извлечение, `memory.enableManagedAutoDream=false` — автоматическую консолидацию. Эти настройки позволяют отделить основной рабочий цикл от дополнительной модельной нагрузки. Количество API-запросов без определения их назначения не показывает эффективность основного цикла.

Микросжатие может очищать старые результаты инструментов из модельной истории. Это не удаление исходных файлов. Для точной работы с документом после сжатия нужно восстановить необходимые сведения чтением канонического источника. Длинная сессия требует отдельной проверки; общий критерий — [контракт исполнения](agent-runtime-contract.md).

## Обновления

Git-установка с включённым обновлением источника отличается от локального импорта. Настройка `autoUpdate` для расширения задаёт участие в проверках, но локальная копия не становится удалённым отслеживаемым источником от самого факта конвертации. Обновление самого Qwen и обновление расширения — разные механизмы.

Наличие проверки обновлений в TUI нельзя автоматически переносить на ACP. Нужно проверять установленные файлы после создания ACP-сессии и момент загрузки нового содержимого. Успешная CLI-проверка каталога не доказывает автоматическое применение в оболочке. Для гарантии нового релиза нужна явная политика источника и активации.

## Лицензия и границы исполнения

Qwen Code распространяется по [Apache-2.0](https://github.com/QwenLM/qwen-code/blob/main/LICENSE). Поддержка собственного провайдера отделяет CLI от конкретного облачного модельного сервиса; юридические условия сервиса остаются самостоятельными. См. [сторонние модели](third-party-models.md) и [региональные условия](harness-regional-availability.md).

Разрешения и sandbox зависят от настроек оператора. Установка расширения, подтверждение command-хуков и ограничение доступа инструментов — разные границы, каждую нужно проверять в выбранном интерфейсе запуска.

# Региональная доступность AI-харнессов

## Кратко

Открытая лицензия харнесса, разрешение использовать его runtime и доступность модельного сервиса — отдельные условия. Собственный endpoint может убрать зависимость от API конкретного поставщика, но не меняет лицензию исполняемого ПО. Для использования из РФ нужно проверять состав системы и текущие правила поставщиков; отсутствие страны в списке сервиса не является само по себе выводом об уголовной незаконности использования программы.

## Что проверять отдельно

| Уровень | Что устанавливает источник |
|---|---|
| Код харнесса | `LICENSE` конкретного проекта: разрешены ли использование, изменение и распространение |
| Исполняемые зависимости | Лицензии встроенных бинарей и других компонентов; OSS-обёртка не лицензирует чужой runtime |
| Модельный сервис | Условия аккаунта и API, поддерживаемые страны, ограничения на пользователей и организации |
| Другие подключения | Собственные условия MCP-серверов, облака и внешних сервисов |
| Конкретный способ использования | Применимые договоры и законодательство, статус организации, обработка и передача данных |

Страна размещения API-сервера и страна, где поставщик разрешает пользоваться сервисом, — разные вещи. Наличие технического подключения не подтверждает договорную допустимость. Списки стран и условия могут меняться; их проверяют перед развёртыванием и при изменении состава системы.

## Codex: OSS CLI и сервисы OpenAI

У [Codex CLI — Apache 2.0](https://github.com/openai/codex/blob/main/LICENSE), с мировой лицензией без отдельного исключения РФ. Это основание рассматривать самостоятельное использование CLI с другой моделью; лицензия не предоставляет доступ к ChatGPT или OpenAI API.

[Конфигурация Codex](https://developers.openai.com/codex/config-reference) предусматривает отдельный модельный провайдер, его `base_url` и собственную авторизацию; `requires_openai_auth` у custom-провайдера по умолчанию выключен. Совместимость endpoint с требуемым протоколом проверяется отдельно — см. [сторонние модели](third-party-models.md).

РФ отсутствует в [списке стран OpenAI API](https://developers.openai.com/api/docs/supported-countries). Поставщик предупреждает о блокировке или приостановке аккаунта при доступе вне списка. Это правило доступа к сервису, которое следует отличать от лицензии OSS-кода.

## Claude Code и Claude Agent SDK

[Claude Code](https://github.com/anthropics/claude-code/blob/main/LICENSE.md) распространяется с сохранением прав Anthropic и отсылкой к Commercial Terms, а не по OSS-лицензии. [Claude Agent SDK](../agents/claude-agent-sdk.md) по умолчанию запускает этот runtime; MIT-лицензия Python-обёртки не меняет его условия.

По [Supported Regions Policy Anthropic](https://www.anthropic.com/supported-countries), проверенной 2026-10-13, РФ не поддерживается. Политика прямо включает Claude Code и модели через облачные платформы и авторизованных реселлеров; учитывает физическое нахождение пользователя, регистрацию или штаб-квартиру организации, а также владение большинством её долей или прямой/косвенный контроль со стороны лиц либо организаций из неподдерживаемых регионов.

[Commercial Terms, раздел D.2](https://www.anthropic.com/legal/commercial-terms), включают региональную политику. Bedrock, Google Cloud и Foundry — способы подключения, а не общее исключение из неё. Смена модельного endpoint при сохранении Claude Code runtime также не даёт опубликованного исключения.

Это препятствие для выбора стандартной поставки Claude Code/Agent SDK как среды с разрешённым поставщиком использованием из РФ. Оно не отменяет MIT-права на отдельно покрытый код Python SDK и не является заключением о российском уголовном праве.

## Граница вывода

Для OSS-харнесса с собственным или локальным модельным провайдером проверяют лицензии каждого компонента и условия выбранных сервисов. Из отсутствия территориального запрета в `LICENSE` нельзя вывести универсальную правовую допустимость любого применения; из недоступности зарубежного API нельзя вывести запрет на OSS CLI.

Если публикации поставщика оставляют неоднозначность для конкретной конфигурации, требуется уточнение условий или правовая оценка этого случая. Технический прогон проверяет работоспособность, а не заменяет такую оценку.

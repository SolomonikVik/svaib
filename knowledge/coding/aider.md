# Aider

## Кратко

Aider — открытый инструмент работы с кодом и файлами через модель, с контекстом проекта, редактированием, Git, lint и test-командами. Его чтение Markdown и загрузка сценария чата не равны установке Agent Skills, MCP и lifecycle-хуков из Claude/Codex-плагина. Подключение к оболочке через ACP может потребовать отдельного моста.

## Что предоставляет Aider

Контекст можно передавать через файлы для чтения и редактирования; настройки задают модель, режим правок и команды проверки. `--read` добавляет файл в контекст, `--load` загружает сценарий сообщений. Это способы подачи текста агенту, а не реестр плагинов с исполняемыми обработчиками. См. [CLI options](https://aider.chat/docs/config/options.html).

В исследованном интерфейсе Aider нет нативного полного установщика Claude/Codex marketplace, совмещающего skill registry, MCP declarations, lifecycle-хуки и агентные профили. Встроенные Git, lint и test-механизмы обслуживают цикл правки кода и не эквивалентны событиям `UserPromptSubmit`, `PreToolUse` и `Stop`. Это граница рассматриваемого интерфейса, а не утверждение, что такие механизмы невозможно добавить в будущих версиях.

Для плагина, который требует этих событий, нужен внешний оркестратор либо специальная интеграция с Aider. Подключение нескольких инструкций через `--read` не подтверждает работоспособность обработчиков, авторизации MCP и правил завершения ответа. Общие границы — в [контракте исполнения](agent-runtime-contract.md).

## Модель и лимиты

Aider поддерживает разных провайдеров. Для отсутствующей в каталоге модели можно задать метаданные и model settings; окно контекста и лимит выхода должны соответствовать реальному endpoint. Заявленная поддержка модели не доказывает качество её правок и работу всех выбранных режимов редактирования. См. [настройку модели](https://aider.chat/docs/config/adv-model-settings.html).

Лицензия харнесса не задаёт условия модельного сервиса. Требования к протоколу и провайдеру нужно проверять для конкретного подключения; общая рамка сравнения описана в [сторонних моделях](third-party-models.md).

## ACP-мосты

ACP-подключение может обеспечивать отдельный проект сообщества. Такой мост имеет свою версию, модельные настройки, поддержку разрешений и MCP; наличие Aider под ним не гарантирует перенос настроек CLI.

В [aider-acp](https://github.com/jorgejhms/aider-acp) путь создания сессии задаёт модель в коде, а переданные клиентом MCP servers не становятся активным MCP runtime. Для другой модели нужно менять этот путь либо выбирать мост с соответствующей конфигурацией. Проверять следует актуальную реализацию, а не только успешный ACP initialize. См. [создание ACP-сессии](https://github.com/jorgejhms/aider-acp/blob/main/src/acp-agent.ts).

Интерфейс оболочки и ограничения моста — отдельные части интеграции. Роль оболочки описана в [BB](../tools/bb.md).

## Обновления и лицензия

`--check-update` и `--upgrade` относятся к самому Aider. Они не являются политикой обновления внешнего агентного плагина или ACP-моста. У этих компонентов должны быть собственные отслеживаемые источники и момент активации.

Aider распространяется по [Apache-2.0](https://github.com/Aider-AI/aider/blob/main/LICENSE.txt). Лицензию выбранного ACP-моста и условия провайдера нужно проверять отдельно; [региональные условия](harness-regional-availability.md) не следуют из открытости основного CLI.

# Pi — совместимость Claude/Codex-плагинов, Python-хуки и обновления

## Кратко

Pi coding agent расширяется через JS/TS API и может переиспользовать содержание Claude/Codex-плагина через общий мост, сохраняя Python-обработчики. Готовые расширения закрывают отдельные части переноса, но импорт скиллов не даёт полной совместимости пакета. Обновление Pi-пакета и обновление импортированного Claude marketplace — разные механизмы.

## Ресурсы и модель

Pi обнаруживает `SKILL.md` из подключённых каталогов. Репозиторий marketplace и каталог самого плагина имеют разную структуру: успешное клонирование корня не доказывает загрузку скиллов, хуков, агентов или MCP. Переходы между форматами нужно проверять по компонентам. [Пакеты](https://pi.dev/docs/latest/packages), [скиллы](https://pi.dev/docs/latest/skills).

Pi требует модельного провайдера; endpoint, ключ, контекстное окно и выходной бюджет задаются отдельно. OpenAI-compatible API недостаточно проверить одним текстовым ответом: нужны инструменты, дочерние сессии и управление длинным контекстом. В актуальной документированной ветке есть встроенный MCP; нельзя переносить старое утверждение об отсутствии MCP на неё. Авторизация OAuth остаётся отдельной операцией. [Модели](https://pi.dev/docs/latest/models), [MCP](https://pi.dev/docs/latest/mcp).

## Готовые расширения и их границы

| Расширение | Что даёт | Что не следует из его установки |
|---|---|---|
| [pi-claude-plugins](https://github.com/ross-jill-ws/pi-claude-plugins) | Импорт скиллов и Markdown-команд из Claude marketplace/cache | Установка и обновление источника, запуск hooks, MCP и agents |
| [pi-hooks](https://github.com/hsingjui/pi-hooks) | Исполнение Claude command-хуков из настроек Pi | Автоматическое обнаружение plugin hooks.json, окружение и одинаковые инструменты |
| [pi-subagents](https://github.com/tintinweb/pi-subagents) | Дочерние сессии и описания агентов | Совместимость Claude-имён инструментов и нужная политика наследования контекста |
| [pi-extmgr](https://github.com/ayagmar/pi-extmgr) | Каталог и проверки обновлений пакетов | Автоматическое применение любого нового релиза |
| [pi-updater](https://github.com/tonze/pi-updater) | Проверка и применение обновлений через выбор пользователя | Обновление импортированного стороннего marketplace и безусловный startup-update |

Пути глобальных настроек у сторонних расширений могут строиться через домашнюю папку, не через переменную каталога Pi. Изоляцию стенда проверяют по фактическим путям, а не одному environment override.

## Python-хуки и субагенты

Логику Python можно сохранить за extension-мостом. Он обнаруживает ресурсы пакета, задаёт корень, нормализует имена инструментов и аргументы, переводит дополнительный контекст и отказ до исполнения инструмента. Только замена matcher не исправляет вход Python-обработчика. [Extension API](https://pi.dev/docs/latest/extensions), [общий контракт хуков](../../plugins/cross-harness-hooks.md).

Описания агентов также требуют перевода allowlist в доступные Pi-инструменты. Изоляцию дочерней сессии проверяют реальным чтением и отсутствием родительского контекста, который не передавали. Обнаруженный Markdown-файл агента сам по себе этого не доказывает.

`agent_end` с дополнительным запросом и точка `agent_before_settle` — разные способы продолжения. Формат Pi JSONL отличается от Claude. Для проверки последнего ответа предпочтителен текст из события или нормализованного состояния сессии; проекция всего транскрипта нужна только при отсутствии такого входа.

## Обновления: пакет Pi и импортированный marketplace

Обычная загрузка установленного пакета не означает fetch источника. Явный `pi update` обновляет зарегистрированные источники; закреплённые теги и commits фиксируют версию и не выбирают следующий стабильный релиз автоматически. Импорт каталога через `pi-claude-plugins` не превращает его источник в управляемый Pi-пакет. [Пакеты Pi](https://pi.dev/docs/latest/packages).

Проверка источника, уведомление, применение и переключение открытой сессии — четыре разных действия. Поведение интерактивного `/update` нельзя автоматически приписывать SDK-интеграции в другом интерфейсе. Общая модель согласованности — [источники, версии и пути хуков](../../plugins/plugin-update-hook-paths.md).

## Разрешения и длинные сессии

Доверие проекту в Pi не является OS-sandbox или подтверждением каждого инструмента. Инструменты и расширения работают с правами локального пользователя; нужную файловую изоляцию предоставляет окружение. [Безопасность Pi](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/security.md).

Compaction заменяет часть модельного контекста, но не обязательно удаляет полную запись сессии или файлы. Перенос адаптера проверяют также после сжатия и возобновления, включая повторную подачу инструкций. [Compaction](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md).

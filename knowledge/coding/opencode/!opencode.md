# OpenCode — совместимость расширений, хуки и особенности V2

## Кратко

OpenCode V2 использует собственный JS/TS-контракт расширений. Claude/Codex-манифест, command-хуки и MCP-настройка не образуют готовый OpenCode-плагин, хотя независимые скиллы и Python-библиотеки можно сохранить. Перенос требует проверки установки, контекста, инструментов, отказов и жизненного цикла отдельно.

## Упаковка и ресурсы

Для npm-совместимой установки нужен `package.json` и исполняемый entrypoint с `id` и `setup(ctx)`. Claude marketplace в `.claude-plugin/` не заменяет этот контракт. Git-селектор каталога выбирает источник, но не конвертирует его. [Управление плагинами](https://dev.opencode.ai/v2/docs/plugins#manage), [создание V2-плагина](https://dev.opencode.ai/v2/docs/build/plugins).

V1 и V2 имеют разные API: V1 возвращает объект обработчиков, V2 регистрирует их из `setup(ctx)`. Реализация V1 не становится V2-плагином после переименования файла или настройки. Общая поставка может поддерживать обе версии через отдельные реализации API. Страницы `opencode.ai/docs/` описывают V1; документация V2 находится на `dev.opencode.ai/v2/docs/`. [Миграция V1 → V2](https://dev.opencode.ai/v2/docs/build/plugins/migrate-v1), [поддержка обеих версий](https://dev.opencode.ai/v2/docs/build/plugins#support-v1).

| Ресурс | Контракт V2 |
|---|---|
| Скиллы | Обнаруживаются в `.opencode/skills`, `.claude/skills`, `.agents/skills` проекта и соответствующих глобальных каталогах; дополнительные каталоги задаются массивом `skills`. ID определяется путём, `name` — отображаемое имя; ID должны быть уникальными. [Discovery и ID](https://dev.opencode.ai/v2/docs/skills/#discovery) |
| Субагенты | Регистрируются с `mode: subagent`, разрешениями и запуском дочерней сессии. Claude-поля `context: fork` и `background` сами по себе не подтверждают изоляцию. [Режимы агентов](https://dev.opencode.ai/v2/docs/agents/#modes) |
| Инструкция проекта | Читается `AGENTS.md`; V2 не использует `CLAUDE.md` как fallback. [Инструкции V2](https://dev.opencode.ai/v2/docs/instructions/) |

`SKILL.md` можно подключать отдельно от упаковки плагина. Каталог `<claude-plugin>/skills` не становится источником только из-за записи в Claude-манифесте. Объявление источника скиллов, субагента и MCP проверяют независимо; наличие всех каталогов в скачанном архиве не доказывает их регистрацию.

## Контракт хуков

| Задача | Точка V2 | Граница проверки |
|---|---|---|
| Контекст исходящего запроса | Session `context` | Контекст попал в реальный запрос нужной сессии |
| Обработка пользовательского ввода | Session `prompt` | Это приём запроса, не событие перед каждой модельной генерацией |
| Результат инструмента | Tool `execute.after` | Нормализованы имя, аргументы и результат, включая MCP |
| Отказ до записи | Tool `execute.before`, permission `evaluate` | Файл ещё не изменён; отказ дошёл до модели |
| Сжатие | Session `compaction` | Инструкции и состояние восстановлены в правильный момент |
| Завершение хода | Проверяется отдельно | Наблюдение за концом ответа не доказывает способность продолжить его |

События здесь — кандидаты соответствия, а не готовая реализация Claude-семантики. В документированном V2 API прямой эквивалент блокирующего Claude Stop не подтверждён. [Хуки V2](https://dev.opencode.ai/v2/docs/build/plugins#hooks), [миграция API](https://dev.opencode.ai/v2/docs/build/plugins/migrate-v1#register-hooks-in-setup).

Session `prompt` меняет сохраняемый пользовательский ввод. Session `context` меняет исходящий запрос, включая продолжения после инструментов. Постоянные инструкции поэтому нельзя привязывать только к приёму пользовательского сообщения.

## MCP, Code Mode и идентичность

Сервер объявляется в `mcp.servers.<name>`; удалённый сервер использует `type: remote`. Claude `.mcp.json` не служит конфигурацией OpenCode. [Конфигурация MCP V2](https://dev.opencode.ai/v2/docs/mcp-servers/#config).

MCP может быть сгруппирован в Code Mode как `tools.<server>.<tool>(...)`; при прямой экспозиции используются имена вида `<server>_<tool>`. Claude matcher `mcp__…__whoami` не универсален. Нужно проверять наблюдение вложенного вызова и получение его результата, а не только регистрацию сервера. [Имена](https://dev.opencode.ai/v2/docs/mcp-servers/#names), [Code Mode и разрешения](https://dev.opencode.ai/v2/docs/mcp-servers/#permissions).

OAuth поддерживается; ручная авторизация не означает несовместимость плагина. Идентичность пользователя и ключи состояния берут из проверенного контракта хоста, не из настроек чужого CLI. Корень, сессия и дочерний агент должны быть явно разделены.

## Проверка переноса

Сбой записи кэша или отсутствие launcher в PATH нужно отличать от ошибки формата пакета. После успешной установки отдельно проверяют Python-зависимости, отказ первой записи, повтор, compaction, субагента и обновление. Исходную Python-логику можно запускать из моста; одинаковые названия событий сами по себе не сохраняют её поведение.

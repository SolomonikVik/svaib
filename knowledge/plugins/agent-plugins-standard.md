# Agent Plugins 1.0

## Кратко

Открытый вендор-нейтральный стандарт упаковки расширений AI-агентов в переносимую папку: манифест `plugin.json` в корне плюс два компонента — Agent Skills (`skills/*/SKILL.md`) и MCP-серверы (`mcp.json`). Опубликован в августе 2026 техкомитетом из Amazon/AWS, Cursor, Microsoft и GitHub, OpenAI, Vercel. Оба упакованных компонента родом из Anthropic (MCP, Agent Skills), но самой Anthropic в стандарте нет. Стандарт покрывает только упаковку и discovery: хуки, команды, субагенты, дистрибуция, права и секреты явно оставлены клиентам.

## Что стандартизировано

Ровно два типа компонентов, оба — в фиксированных местах:

| Компонент | Путь | Правило |
|-----------|------|---------|
| Agent Skills | `skills/<name>/SKILL.md` | только прямые потомки `skills/`, без рекурсии |
| MCP-серверы | `mcp.json` в корне плагина | один файл, объект `mcpServers` |

Отсутствие обеих локаций — не ошибка. Если локация есть, но не того типа (например `skills` — файл, а не папка), невалидным считается только этот тип компонента, остальные продолжают грузиться. Симлинки разрешены, пока разрешаются внутрь корня плагина; выход за корень отклоняется.

```
my-plugin/
├── plugin.json              # манифест, обязателен, в КОРНЕ
├── skills/
│   └── summarize/
│       ├── SKILL.md
│       ├── scripts/
│       └── references/
├── mcp.json                 # MCP-серверы
└── com.example.client/      # клиентское расширение по reverse-domain
    └── hooks/
```

## Манифест plugin.json

Схема **закрытая** (`additionalProperties: false`). Обязательны два поля.

| Поле | Тип | Обяз. | Примечание |
|------|-----|-------|-----------|
| `$schema` | string | да | константа `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` |
| `name` | string | да | 1–64 симв., `[a-z0-9.-]`, без подряд идущих `--` и `..` |
| `version` | string | нет | рекомендован SemVer |
| `description` | string | нет | |
| `author` | object | нет | `name`, `email`, `url` — все опциональны |
| `homepage`, `repository`, `license` | string | нет | лицензия — SPDX-идентификатор |
| `keywords` | string[] | нет | для discovery |
| `extensions` | object | нет | клиентские данные по namespace |

Минимальный валидный манифест:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "hello-plugin"
}
```

Неизвестные поля верхнего уровня — сообщаются, но не фатальны. Прочие нарушения схемы отклоняют плагин целиком.

## mcp.json

Свой `$schema` (`.../mcp.schema.json`) и объект `mcpServers` — больше на верхнем уровне ничего. Запись сервера — закрытое объединение по полю `type`:

| Транспорт | Обязательные поля | Опциональные |
|-----------|-------------------|--------------|
| `stdio` | `command` (одиночный исполняемый токен) | `args`, `env`, `cwd` |
| `streamable-http` | `url` (абсолютный http/https, без user-info и фрагмента) | `headers` |
| `sse` (legacy) | `url` | `headers` |

Клиент ОБЯЗАН поддерживать хотя бы один из `stdio` / `streamable-http`; `sse` опционален. `headers` подстановку переменных не поддерживают.

## Переменные плагина

Две зарезервированные переменные, которые клиент передаёт подпроцессам:

- `PLUGIN_ROOT` — абсолютный путь к корню плагина;
- `PLUGIN_DATA` — абсолютный путь к персистентному каталогу данных, создаётся клиентом, доступен на запись и **переживает обновления плагина**.

Подстановка `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` — однократная, нерекурсивная, текстовая. Применяется к строкам в `args`, значениям в `env` и к `cwd`. Не применяется к ключам `env`, к `command` и к фиксированным путям компонентов. Никакого раскрытия обычных переменных окружения нет; неопознанный плейсхолдер остаётся литералом. Сервер с ключом `PLUGIN_ROOT` или `PLUGIN_DATA` внутри `env` считается невалидным.

## Клиентские расширения через namespace

Всё, что стандарт не описывает, кладётся под идентификатором в стиле reverse-domain (`com.example.client`) — в двух местах сразу:

```json
"extensions": {
  "com.example.client": { "setting": true }
}
```

и одноимённая папка в корне плагина (`com.example.client/hooks/hooks.json`). Содержимое папки клиент определяет сам. Клиент, не реализующий namespace, обязан молча его игнорировать — без валидации. Так один пакет несёт портируемое ядро и клиентские надстройки, не ломая другие клиенты.

## Требования к клиентам (conformance)

Минимальный чеклист: загрузить плагин из папки с `plugin.json` в корне; провалидировать манифест по закрытой схеме, не падая на нефатальных отклонениях; игнорировать нереализованные namespace; искать компоненты только в фиксированных локациях; поддерживать хотя бы один тип компонента (можно skills-only); при запуске подпроцессов отдавать `PLUGIN_ROOT`/`PLUGIN_DATA` и раскрывать их в `args`/`env`/`cwd`; трактовать `command` как одиночный исполняемый токен, а корень плагина — как рабочую директорию по умолчанию; пропускать невалидные записи, продолжая грузить независимые; отклонять пути и симлинки за пределы корня.

Частичное соответствие разрешено явно — клиент может поддерживать только скиллы и всё равно быть конформным.

## Что вне scope v1

Умышленно не покрыто: хуки и события жизненного цикла; slash-команды; агенты и правила; LSP-серверы; дистрибуция, реестры и маркетплейсы; модели прав и sandboxing; OAuth и хранение секретов (`headers` и `env` — видимые данные пакета, портабельного механизма секретов нет); поведение при отказе транспорта; управление зависимостями и разрешение версий.

Логика авторов: стандартизировать только переносимое ядро, оставив конкуренцию продуктам. Формулировка Vercel — commands, hooks и субагенты «остаются у клиентов».

## Кто за стандартом и кто поддерживает

Техкомитет: Amazon/AWS, Cursor, Microsoft и GitHub, OpenAI, Vercel. Спецификация и предложения — публично на GitHub ([agentplugins/agent-plugins-spec](https://github.com/agentplugins/agent-plugins-spec)), обсуждения через GitHub Discussions.

Клиенты с нативной поддержкой на старте: ChatGPT, Codex, Cursor, GitHub Copilot, Kiro, VS Code. Ещё несколько получают плагины через CLI-трансляцию (см. ниже): Claude Code, Grok Build, Kimi Code.

## Отношение к формату Anthropic

Оба компонента стандарта созданы Anthropic: MCP (ноябрь 2024) и Agent Skills (открытый стандарт с декабря 2025). При этом Anthropic не входит ни в техкомитет, ни в список launch-партнёров, а её собственный формат плагинов Claude Code / Cowork с Agent Plugins несовместим:

| Что | Формат Anthropic | Agent Plugins 1.0 |
|-----|------------------|-------------------|
| Манифест | `.claude-plugin/plugin.json` | `./plugin.json` — то же имя файла, несовместимая схема |
| MCP-конфиг | `.mcp.json` | `mcp.json` |
| Хуки | `hooks/hooks.json`, 13 событий, 3 типа | вне стандарта |
| Команды, субагенты, LSP | `commands/`, `agents/`, `.lsp.json` | вне стандарта |
| Переменные | `${CLAUDE_PLUGIN_ROOT}` | `${PLUGIN_ROOT}`, `${PLUGIN_DATA}` |
| Дистрибуция | Git-маркетплейсы (`marketplace.json`), scopes, авто-обновление | не покрыта |

Совпадение имени `plugin.json` при разных схемах и разном расположении — известная коллизия, из-за которой клиенту приходится определять формат, а не просто читать файл. VS Code, например, распознаёт четыре варианта: Agent Plugins 1.0 (`plugin.json` с `$schema`), Copilot (`plugin.json` без схемы), Claude (`.claude-plugin/plugin.json`) и legacy OpenPlugin (`.plugin/plugin.json`).

Читается это не как отставание Anthropic, а как разделение зон: стандарт фиксирует переносимое ядро, а конкурентное преимущество Anthropic лежит ровно в непокрытой обёртке — хуках, маркетплейсах, enterprise-scopes.

Отдельная деталь ландшафта: нейтральная площадка, где Anthropic и OpenAI уже соучредители, существует — это AAIF под Linux Foundation с якорными проектами MCP, AGENTS.md и goose ([../context/ai-system-files.md](../context/ai-system-files.md)). Agent Plugins создан вне её, собственным техкомитетом.

## CLI и трансляция: что переживает перенос

`npx plugins add <owner>/<repo>` — CLI, распознающий установленные цели и переводящий нейтральный формат в нативный формат каждой из них, после чего установка идёт штатным механизмом клиента. Плагин доставляется из GitHub (репозиторий служит идентификатором, git-теги — версиями), кэшируется локально shallow-клоном.

Поддерживаемые цели включают Claude Code, Cursor, Codex, GitHub Copilot CLI, VS Code, Grok Build, Kimi Code.

**Важное различие:** «плагины ставятся в Claude Code» ≠ «Claude Code нативно поддерживает Agent Plugins». Нативного парсинга AP-манифеста нет — CLI конвертирует пакет в проприетарную структуру `.claude-plugin/`.

При трансляции надёжно переживают перенос только скиллы и MCP-конфигурация. Slash-команды переносятся маппингом клиента, хуки и субагенты **отбрасываются** — портабельного эквивалента для них не существует. Практический вывод для авторов: держать `SKILL.md` чистыми и стандартными, MCP-конфиги — декларативными, а всё клиентское уводить в namespace.

## Ограничения и открытые вопросы

- **Discovery не решён.** Стандарт задаёт формат, но не отвечает на вопрос «какой плагин закрывает мою задачу» — реестра или поисковой службы в спеке нет.
- **Доверие и аудит.** Стандарт не вводит ни подписи, ни требований к происхождению кода; проблема непроверяемых MCP-серверов остаётся снаружи.
- **Права разные у всех.** Один и тот же плагин получает разный объём привилегий в разных клиентах — модель прав вне стандарта.
- **Автоматика непереносима.** Пока hooks/commands/agents вне спеки, любой плагин с enforcement-логикой остаётся частично клиентским.
- **Секреты некуда положить.** Портабельного механизма для токенов и OAuth нет.

Открытые направления: нативная поддержка формата у невходящих вендоров и возможное расширение scope в следующих версиях.

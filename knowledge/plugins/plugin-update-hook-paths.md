# Обновление плагина и пути хуков в Codex и Claude Code

## Кратко

Каталоги версий установленного плагина создаёт и очищает харнес; автор плагина задаёт версию в манифесте и использует предоставленный хостом путь. В Codex удаление старой версии может опередить обновление обработчиков хуков открытых сессий. Claude Code сохраняет старые каталоги на 14 дней, поэтому этот сценарий немедленного исчезновения файлов при обновлении там предотвращён; поведение других харнесов не установлено.

## Кто создаёт каталоги

Для установки из маркетплейса Codex использует `~/.codex/plugins/cache/<marketplace>/<plugin>/<version>/`, Claude Code — `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`. Это устройство хостов, а не механизм конкретного плагина. Хост передаёт абсолютный путь установленной версии через `CLAUDE_PLUGIN_ROOT`; Codex также предоставляет `PLUGIN_ROOT`. [Размещение в Codex](https://developers.openai.com/plugins/build/plugins#how-local-marketplaces-work), [размещение в Claude Code](https://code.claude.com/docs/en/plugins/loading#find-plugins-on-disk).

Старый путь в открытой сессии допустим, пока соответствующий комплект файлов остаётся доступным. Каталоги разных версий позволяют сохранять согласованный код, импорты и ресурсы.

## Codex

Срез на 2026-10-08: официальный Codex **0.161.0**, commit `979011409de0a60b52f179721948e65531d26144`.

- После установки новой версии `remove_old_plugin_versions` сразу удаляет остальные валидные каталоги версий. Активные сессии и срок удержания в этой операции не учитываются. [Код установки и очистки](https://github.com/openai/codex/blob/979011409de0a60b52f179721948e65531d26144/codex-rs/core-plugins/src/store.rs#L648-L724).
- Путь версии сохраняется в окружении загруженного обработчика хука. При запуске команды это окружение используется повторно. [Загрузка обработчика](https://github.com/openai/codex/blob/979011409de0a60b52f179721948e65531d26144/codex-rs/hooks/src/engine/discovery.rs#L253-L288).
- Перезагрузка обработчиков открытых сессий существует, но при ручном обновлении выполняется после изменения файлов; в автоматическом пути вызывается последующим асинхронным уведомлением. Общей атомарной смены файлов и обработчиков нет. [Ручное обновление](https://github.com/openai/codex/blob/979011409de0a60b52f179721948e65531d26144/codex-rs/app-server/src/request_processors/marketplace_processor.rs#L85-L100), [асинхронное уведомление](https://github.com/openai/codex/blob/979011409de0a60b52f179721948e65531d26144/codex-rs/app-server/src/effective_plugin_change.rs#L30-L38).

Между удалением каталога и обновлением обработчиков возможен запуск по старому пути. Это подтверждённый риск механизма обновления; утверждать, что Codex вообще не обновляет хуки живых сессий, неверно.

### Почему ошибка может зациклить ответ

Python при попытке открыть отсутствующий файл скрипта возвращает код `2` и сообщение `can't open file ... [Errno 2]`. Это воспроизведено отдельным запуском отсутствующего файла. Для `Stop`-хука Codex трактует код `2` как требование продолжить ответ и передаёт текст ошибки агенту. Следующий ответ снова может вызвать тот же неработающий хук. [Контракт Stop](https://learn.chatgpt.com/docs/hooks#stop).

Защита от повторного `Stop` внутри скрипта не срабатывает, если Python не может открыть сам скрипт. Причина длительности конкретного цикла на Mac без версии Codex и его логов не установлена.

## Claude Code и другие харнесы

При обновлении Claude Code оставляет текущую сессию на загруженной версии. Старый каталог получает метку `.orphaned_at` и удаляется фоновой очисткой через **14 дней**; `/reload-plugins` переключает хуки на новую версию. Поэтому немедленное удаление файлов старой сессии при штатном обновлении не является её обычным сценарием. Это не гарантия для сессии, оставленной на старой версии дольше срока удержания. [Очистка предыдущих версий](https://code.claude.com/docs/en/plugins/loading#cleanup-of-previous-versions), [применение обновлений](https://code.claude.com/docs/en/plugins/loading#when-auto-update-runs).

В других харнесах удержание версий и переключение хуков не проверены. Совместимость формата плагина сама по себе не гарантирует одинаковый жизненный цикл файлов.

## Практический вывод

Доля затронутых пользователей неизвестна. Для сбоя достаточно одной открытой сессии, если её хук запускается после удаления старого каталога и до обновления обработчиков. Наличие нескольких чатов не является обязательным условием.

Устранить зависимость от очистки кэша можно удержанием используемых версий на стороне хоста либо отдельным исполняемым комплектом вне кэша. Второй путь требует собственной установки, подготовки зависимостей и управления версиями; проверка наличия файла сама по себе лишь предотвращает цикл и не восстанавливает работу хука. Масштаб риска следует сопоставить со стоимостью такого механизма.

Применение в svaib: решение не строить отдельный runtime и не менять поставку.

# Коннектор Google Sheets через Drive MCP

Способ чтения клиентской Google-таблицы без браузерного моста и без сервисного API-доступа: Drive MCP отдаёт книгу целиком в xlsx, дальше работает обычный python-extractor. Проверен на источнике клиента С. 30.07.2026 (книга weekly-метрик, 19 листов, 913 КБ).

Место в вертикали: реализация компонента **extractor** для источников типа Google Sheets. Контракт компонента — [architecture.md](../../../methodology/metrics/architecture.md), раздел «Extractor»; уровень сборки — [extractor.md](../../../methodology/metrics/extractor.md).

**Статус: минимальная часть.** Работает и закрывает три дефекта чтения. Без eval, без точечного обновления, без автоматической инвалидации. Развитие — dev/metrics/fix-plan.md, раздел «Развитие коннектора».

## Почему xlsx, а не CSV

Оба формата доступны через `download_file_content`, но годится только один.

| | CSV (`text/csv`) | xlsx (`…spreadsheetml.sheet`) |
|---|---|---|
| Листы | **только первый**, выбрать нельзя — параметра листа в API нет | **все**, по именам |
| Координаты | номер строки в потоке | нативные A1 |
| Числа | строки: `"6,8%"`, `1 029` с NBSP | нативные float: `0.068`, `1029` |
| base64 | приходит **в контекст модели** | объём превышает лимит → харнесс сохраняет **в файл** |

Последняя строка — не мелочь: контекст модели не место для base64. Крупный экспорт уходит в файл автоматически, и разбор делает python, а не модель. Поэтому правило: **запрашивать xlsx всегда**, даже когда нужен один лист.

## Процедура

1. **Проверить свежесть.** `get_file_metadata` по `fileId` → `modifiedTime`, `title`. Сравнить с меткой уже скачанного snapshot (если он есть в сессии). Не изменился — переиспользовать, не качать заново.
2. **Скачать.** `download_file_content` с `exportMimeType: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. Результат — JSON `{content: base64, …}`, который харнесс сохраняет в файл.
3. **Декодировать питоном** из сохранённого файла в рабочий xlsx. Base64 в контекст модели не поднимать.
4. **Разведать** — [probe_xlsx.py](probe_xlsx.py): листы, размеры, объединённые ячейки, формулы, заполненность. Требует `openpyxl`.
5. **Извлечь** — extractor по канону: канонические имена метрик на входе, значения с метаданными в JSON-файл на выходе, в stdout только статус.
6. **Проверить guard-и** (см. ниже) до того, как значения уйдут в ответ.

## Guard-и

- **Имена листов.** Читать лист, названный в карте источников metrics-файла, а не «похожий». На источнике клиента С. существуют одновременно `Sales Team UAE` (канон) и `Sales Team (upd)` — с расходящимися значениями по одной метрике. 30.07 чтение без имён листов дало значение из неканонического листа, и оно ушло в артефакт. Guard существовал в клиентском скилле и был неисполним, пока не появились имена.
- **Schema-hash** — отпечаток структуры (имена листов, колонок, порядок) снимается при настройке, сверяется при каждом заборе. Не совпало — стоп и сигнал, не чтение «соседней ячейки».
- **Метка-подтверждение строки.** Адрес — не только координата, но и метка: прежде чем брать `H25`, проверить, что в `A24`/`B25` стоят ожидаемые метки. Структуру источника правит клиент, строки съезжают.

## Свежесть и протухание

**Скачанный xlsx — эфемерный snapshot, а не источник правды.** Он живёт ровно столько, сколько собирается артефакт (повестка, ответ на вопрос CEO, сводка), и после этого считается протухшим. Он не кладётся в git, не заменяет клиентскую таблицу и не становится вторым местом хранения значений — иначе вертикаль получает расходящуюся копию данных клиента.

Из этого два следствия, которые нельзя путать:

- **Разовая сборка** (повестка, ad-hoc вопрос) — качаем, собираем, забываем. Простое и правильное поведение по умолчанию.
- **Живая сессия обсуждения метрик** — качать книгу заново на каждый вопрос бессмысленно: источник клиент правит вручную, между двумя вопросами он обычно не меняется. Snapshot переиспользуется внутри сессии.

Граница между режимами определяется **датой изменения файла**, а не таймером: перед каждым обращением к значениям — `get_file_metadata` и сравнение `modifiedTime` с меткой snapshot. Дешёвый вызов метаданных вместо повторной выгрузки книги.

**Что коннектор пока не умеет:** обновить одну строку, не перекачивая книгу; определить дату среза конкретной колонки (известна дата изменения книги, но не то, на какое число актуален «июль»). Оба вопроса — в плане развития.

## Ограничения

- Требует `openpyxl` в окружении.
- `data_only=True` отдаёт кэшированные значения формул: если клиент не открывал книгу после правки формул, значение может быть устаревшим или отсутствовать.
- Датировка колонки не выводится — правило «незакрытый месяц занижен» применяется по календарю, а не по данным (дефект A4.1 в [defects.md](defects.md)).
- Интерактивно-авторизованный MCP может быть недоступен в headless-запуске — смежное ограничение зафиксировано в [product/03_backlog.md](../../../03_backlog.md).

# Анализ встреч

Пайплайн превращает транскрипт встречи в структурированные артефакты. Два основных слоя: L1 (извлечение → выжимка), L2 (выжимка → клиентские форматы + обновление файлов проекта). Перед применением обновлений слой L2.5 проверяет предлагаемые правки.

Методологическое обоснование устройства пайплайна — во внутренней документации разработчика; в клиентскую поставку не входит.

Исполняемая точка входа: [SKILL.md](SKILL.md). Этот README хранит карту компонентов и ручной маршрут запуска.

---

## Пайплайн

**Рабочая версия:** только экстрактор сущностей (используется оркестратором):

```
транскрипт + контекст
         │
         ▼
  Экстрактор сущностей (извлечение + классификация)
         │
         ▼
      Выжимка
         │
    ┌────┼────┐
    ▼    ▼    ▼
 Протокол Telegram Обновление файлов
   (L2)   (L2)    (L2)
                     │
                     ▼
         Ревью предлагаемых правок (L2.5)
                     │
                     ▼
       Показ согласующему → применение
```

Обновление файлов проекта — двухфазный L2: Фаза A собирает дельты на полноту покрытия, Фаза B (канонизатор) назначает каждой сущности единственное каноническое место; code-валидатор (`validate_deltas.py`) прогоняется после каждой фазы и после ревью (на одноузловом пути — одним объединённым вызовом после канонизации), обязательный минимум вызовов задаёт `validation-contract.json`.

Поведенческий экстрактор существует в двух вариантах (v1 аналитический, v2 клиентский), но к пайплайну не подключён.

## Как запустить

**Быстрый старт:**
- Автоматический вызов навыка: пользователь просит обработать встречу или транскрипт
- Внутренняя встреча (подразделения/направления, команда): [orchestrator-meeting.md](orchestrator-meeting.md)
- Встреча с контрагентом (клиент, партнёр): [orchestrator-client-meeting.md](orchestrator-client-meeting.md)

### Что нужно перед стартом (ручной запуск)

- Транскрипт встречи (текст)
- Контекст транскрипта (обязательно): люди, глоссарий (ASR-ошибки, жаргон), тип/цель встречи
- Досье проекта (опционально, подаётся экстрактору сущностей как фон)

Источники контекста зависят от типа встречи:

| Тип встречи | Люди | Глоссарий | Досье |
|-------------|------|-----------|-------|
| Внутренняя | 01_company/02_team/01_org-structure.md + 01_company/glossary.md | 01_company/glossary.md | {org_node}/01_overview.md, 01_company/02_team/{person}.md |
| С контрагентом | profile.md + company.md | из profile/company (если нет выделенного — не угадывать) | 01_overview.md |

### Шаги рабочей версии (только экстрактор сущностей)

**Шаг 1. Запусти экстрактор сущностей.**

| Экстрактор | Промпт | Вход |
|------------|--------|------|
| Сущности | L1-prompt-entity-extractor.md | контекст транскрипта + транскрипт + досье (как фон, опционально) |

Субагенту: прочитай промпт (секция "Промпт" внутри ```блока```), подай вход, верни результат в файл.

> Когда поведенческий экстрактор будет подключён к пайплайну, здесь добавится параллельный шаг и объединение выходов.

**Шаг 2. Запусти промпт Слоя 2.**

- **Протоколы** (полный, Telegram): вход — выжимка + досье (опционально). Транскрипт НЕ подавать
- **Обновление файлов:**
  - Внутренняя встреча: выжимка + контекст от руководителя + файлы подразделения/направления (`{org_node}/`) + 01_company/02_team/
  - Встреча с контрагентом: выжимка + контекст от исполнителя + досье контрагента (profile, company, 01_overview...)

**Шаг 3. Ревью предлагаемых правок (L2.5).** Предложенные обновления файлов проходят независимое ревью (L2-review-procedure.md); согласующий видит разделы «Советую обновить» и «Сомневаюсь», применяются только принятые правки.

## Ответственности координатора

Координатор — это ты (главный агент). Субагенты — исполнители одного промпта.

- **Координатор** запускает экстрактор сущностей (субагент)
- **Координатор** передаёт досье экстрактору сущностей (как фон) и L2-промптам
- **Субагент** получает один промпт + данные, возвращает результат. Не оркестрирует, не запускает других субагентов

## Частые ошибки

| Ошибка | Почему плохо | Как правильно |
|--------|-------------|---------------|
| Дать транскрипт протоколу | Протокол работает по выжимке, не по сырому тексту | Только выжимка + досье |
| Пропустить контекст транскрипта | Модель не знает кто говорит, путает имена | Всегда подавать контекст транскрипта (люди, глоссарий, тип/цель) |

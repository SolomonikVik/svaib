# Анализ встреч

Проведи встречу через полный пайплайн: выжимка → предлагаемые обновления файлов → независимое ревью → согласование → применение → опциональная Telegram-сводка.

## Iron Law

Никогда не применяй предлагаемые L2-обновления файлов базы без явного согласования: сначала покажи выжимку, затем предлагаемые правки после ревью, применяй только принятые.

## Маршрутизация

1. Определи тип встречи по запросу и контексту:
   - внутренняя встреча команды, подразделения, направления или компании → прочитай целиком `orchestrator-meeting.md`;
   - встреча с клиентом, партнёром, подрядчиком или другим контрагентом → прочитай целиком `orchestrator-client-meeting.md`.
2. Если тип неоднозначен, задай один короткий вопрос. Не запускай оба пути.
3. Выбранный оркестратор — источник правды полного процесса. Выполни его с Шага 0 до финализации.

## Правила выполнения

- Не читай транскрипт в основном контексте: путь получает L1-субагент.
- Не загружай все файлы каталога заранее. Читай процедуру или промпт только тогда, когда выбранный оркестратор доходит до соответствующего шага.
- Субагент получает одну задачу и не оркестрирует других субагентов.
- Не заменяй файл-центричный проход раскладыванием сущностей из выжимки.
- На L2.5 следуй `L2-review-procedure.md`: ревьюеры затронутых файлов независимы и в интерактивной среде запускаются одновременно.
- Не переписывай существующий протокол или выжимку без явного согласования.

## Границы

- Несколько контрагентов в одной встрече → сообщи, что текущий путь требует отдельных проходов по досье, и согласуй разделение.
- Стратегическая встреча, меняющая `01_company/01_strategic/`, → останови обновление стратегических файлов: текущий L2 не содержит их чеклиста.
- Не хватает обязательного пути, даты, участников или направления → запроси только недостающие данные.

Карта всех компонентов и статусов пайплайна — в `README.md`.

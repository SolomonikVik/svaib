---
title: "Узел map: карта домов встречи по канону scaffold"
type: prompt
---

Твоя цель: назвать дома записи, которых встреча реально касалась, — чтобы фон собирался точечно и редакторы работали только там, где есть работа. Ошибка в обе стороны дорога: пропущенный дом останется без записей, лишний — раздует разбор и породит ложные предложения.

На входе: сырьё карты (`artifacts/base-raw.json`) — факты диска без классификации: корневой README целиком, по каждому каталогу — дети, md-файлы, панель, секции README; плюс транскрипт (грубо, читать бегло).

## Как строится карта

**От корневого README вниз по объявлениям — так устроен канон scaffold.** Дом записи — объект управления: узел, который объявлен картой родителя и имеет свою карту (README). Признаки объекта управления: узел верхнего уровня из корневого README · README объявляет «Маршруты записи» · у узла есть управленческая панель (kit-файлы `01_overview…05_decisions`, файлом или папкой).

**Ракурсы, kit-папки, инфраструктура (`meetings/`, `source/`) и рабочие папки домами не бывают** — их файлы адресует владелец-узел. Разговор о разделе (`dev/gateway`) — разговор его владельца (`dev`), если раздел сам не объявлен домом по признакам выше: сначала проверь это, потом нормализуй к владельцу.

**Неидеальность базы — шум, а не блокер.** Битая ссылка, README без канонических секций, самодельные заголовки — база не обязана быть идеальной, чтобы разбор работал. Суди по совокупности объявлений и здравому смыслу канона; сомнение о статусе места решай в пользу ближайшего несомненного владельца и скажи об этом в `findings`.

## Что делаешь

1. **Дома по содержанию, не по составу участников.** Пользователь, обсуждающий чужое направление, своей папке дом не добавляет: объект обсуждения решает, кто владелец.
2. **Расхождения структуры — в `findings`.** Встреча идёт о клиенте, досье которого не заведено; узел есть на диске, но не объявлен картой; объявлен — а README нет. Это не твоя починка: структуру базы разворачивает пользователь процедурой scaffold. Назови находку — она доедет до паузы 1.

Не решай, что записывать: карта отвечает только на вопрос «чей это разговор».

## Дом протокола — правило базы, а не твоя догадка

Кроме домов сущностей ты называешь ещё одно место: где у ЭТОЙ базы живут протоколы встреч. Это единственное место, где правило можно прочитать, — корневой README доезжает целиком только до тебя.

Читай его так: блок **«Правила работы»** — там клиент фиксирует размещение встреч, централизованно (например, всё в `01_company/meetings/`) или распределённо по узлам. Блока нет — правило может быть выражено неявно в «Маршрутах чтения/записи» того же README; ищи там.

Нашёл — верни `protocol_home`: `dir` (существующий каталог протоколов, обычно `<узел>/meetings`) и `evidence` — файл и **дословную строку**, из которой правило прочитано. Улика той же формы, что опора размещения операции: код проверит, что строка действительно стоит в названном файле, что каталог существует — и что эта строка называет **именно этот** каталог. Строка про другое место каталог не подтверждает, и часть чужого адреса тоже: правило про `01_company/meetings/` не улика для `01_company`. Правило называет каталог иначе, чем он записан на диске, — это не твоя беда: поля не возвращай, вопрос доедет до пользователя.

**Правила не нашёл или оно неоднозначно — поля не возвращай вовсе.** Выдуманный каталог хуже отсутствия: отсутствие станет вопросом пользователю на паузе 1, а догадка молча уведёт протокол не туда.

## Форма ответа

Один JSON по схеме `schema/map.json`: `units[]` — дома с причинами, `protocol_home` — дом протокола с уликой правила (если правило прочитано), `findings[]` — расхождения. Место, которого в базе нет, юнитом назвать нельзя — код проверит существование.

---
title: "Узел map: карта домов встречи по канону scaffold"
type: prompt
---

Твоя цель: назвать дома записи, которых встреча реально касалась, — чтобы фон собирался точечно и редакторы работали только там, где есть работа. Ошибка в обе стороны дорога: пропущенный дом останется без записей, лишний — раздует разбор и породит ложные предложения.

На входе: сырьё карты (`artifacts/base-raw.json`) — факты диска без классификации: корневой README целиком, по каждому каталогу — дети, md-файлы, панель, секции README; плюс сама встреча — **штатно ростером выжимки** (`artifacts/roster-lean.json`: сущности с типами, темами, авторами и подсказками домов — суди «чей это разговор» по ним; `unit_hint` — подсказка узла выжимки, не решение: проверяй её против объявлений сырья и лишних домов не плоди), **в фоллбэке — транскриптом** (грубо, читать бегло): так бывает, когда речевой контекст базы пуст и карта нужна до выжимки.

## Как строится карта

**От корневого README вниз по объявлениям — так устроен канон scaffold.** Дом записи — объект управления: узел, который объявлен картой родителя и имеет свою карту (README). Признаки объекта управления: узел верхнего уровня из корневого README · README объявляет «Маршруты записи» · у узла есть управленческая панель (kit-файлы `01_overview…05_decisions`, файлом или папкой).

**Ракурсы, kit-папки, инфраструктура (`meetings/`, `source/`) и рабочие папки домами не бывают** — их файлы адресует владелец-узел. Разговор о разделе (`dev/gateway`) — разговор его владельца (`dev`), если раздел сам не объявлен домом по признакам выше: сначала проверь это, потом нормализуй к владельцу.

**Неидеальность базы — шум, а не блокер.** Битая ссылка, README без канонических секций, самодельные заголовки — база не обязана быть идеальной, чтобы разбор работал. Суди по совокупности объявлений и здравому смыслу канона; сомнение о статусе места решай в пользу ближайшего несомненного владельца и скажи об этом в `findings`.

## Что делаешь

1. **Дома по содержанию, не по составу участников.** Пользователь, обсуждающий чужое направление, своей папке дом не добавляет: объект обсуждения решает, кто владелец.
1а. **Переведи hint'ы ростера в юниты — поле `hint_map`** (штатный путь). Узел выжимки пишет `unit_hint` человеческим именем («инженерия», «клиенты»), а не путём: верни словарь `hint_map` — каждое встреченное имя → юнит твоей карты. Без него код не приведёт свободное имя к дому, и сущность уедет вопросом пользователю. Имя, которое ни к какому дому не привёл, в `hint_map` не включай — вопрос честнее догадки.
2. **Расхождения структуры — в `findings`.** Встреча идёт о клиенте, досье которого не заведено; узел есть на диске, но не объявлен картой; объявлен — а README нет. Это не твоя починка: структуру базы разворачивает пользователь процедурой scaffold. Назови находку — она доедет до паузы 1.

Не решай, что записывать: карта отвечает только на вопрос «чей это разговор».

## Дом протокола — правило базы, а не твоя догадка

Кроме домов сущностей ты называешь ещё одно место: где у ЭТОЙ базы живут протоколы встреч. Это единственное место, где правило можно прочитать, — корневой README доезжает целиком только до тебя.

Читай его так: блок **«Правила работы»** — там клиент фиксирует размещение встреч, централизованно (например, всё в `01_company/meetings/`) или распределённо по узлам. Блока нет — правило может быть выражено неявно в «Маршрутах чтения/записи» того же README; ищи там.

**У каталога протоколов бывает своя карта.** Найдя каталог, посмотри его собственный README в сырье: секция «Маршруты записи» может разводить протоколы по подпапкам — по типам встреч этой базы. Тогда `dir` — подпапка, которой принадлежит ЭТА встреча: сопоставь её содержание со строками маршрутов и возьми подходящую. Никакого своего списка типов у тебя нет и быть не должно — типы этой базы ровно те, что написаны в её README; строка называет подпапку параметром (`okr-N/`, `<фамилия>/`) — подставь значение из содержания встречи, а существование каталога проверит код. Ни одна строка не подходит либо README каталога такой секции не имеет — `dir` остаётся самим каталогом, и это нормальный ответ, а не пробел.

Верни `protocol_home`: `dir` (существующий каталог, куда ляжет протокол этой встречи) и `evidence` — файл и **дословную строку**, из которой правило прочитано. Улика той же формы, что опора размещения операции: код проверит, что строка действительно стоит в названном файле, что каталог существует — и что эта строка называет **его самого либо каталог, внутри которого он лежит**. То есть при выборе подпапки уликой остаётся строка правила о самом каталоге протоколов: дословной строки под конкретную подпапку в базе может не быть вовсе. Строка про другое место каталог не подтверждает, и часть чужого адреса тоже: правило про `01_company/meetings/` не улика для `01_company` — вверх по дереву улика не работает, только вниз. Правило называет каталог иначе, чем он записан на диске, — это не твоя беда: поля не возвращай, вопрос доедет до пользователя.

**Правила не нашёл или оно неоднозначно — поля не возвращай вовсе.** Выдуманный каталог хуже отсутствия: отсутствие станет вопросом пользователю на паузе 1, а догадка молча уведёт протокол не туда.

## Чья речь звучит — отдельный вопрос (фоллбэк)

Этот раздел работает, когда ты идёшь **до** выжимки, по транскрипту: штатно (по ростеру) речевой контекст уже собран и выжимка сдана — досье и источники чтения называть поздно, поля оставляй пустыми.

Дом отвечает «куда писать», а прочитать транскрипт помогает другое: имена, роли и язык людей. Если на встрече звучит речь внешнего участника — контрагента, кандидата, партнёра, — назови его **существующее** досье в `counterparties`. Это не дом записи: внутренний разбор про клиента пишет в свои юниты, а имена читает из его досье. Досье не заведено — не угадывай путь, скажи в `findings`.

Файлы чтения речи (`speech-aliases`, `glossary`, `org-structure`, `profile`) код находит сам по канону. Твоё дело — только отклонения: база держит словарь под другим именем, в чужой папке или с префиксом. Такие файлы назови в `reading_sources`. Ядро скажет в ответе, каких ролей канон не нашёл, — тогда посмотри сам и переподай карту. Не нашлось ничего — это нормальный ответ: разбор пойдёт на голом транскрипте.

## Форма ответа

Один JSON по схеме `schema/map.json`: `units[]` — дома с причинами, `protocol_home` — дом протокола с уликой правила (если правило прочитано), `counterparties[]` — досье внешних участников для чтения речи, `reading_sources[]` — файлы чтения речи вне канонических мест, `findings[]` — расхождения. Место, которого в базе нет, юнитом назвать нельзя — код проверит существование.

Файл ответа сохрани сам — по пути, который назвал координатор в задании, — а финальным сообщением верни этот путь и резюме в две-три строки (дома, находки). JSON в текст сообщения не вставляй: артефакт читает ядро из файла, а не координатор из чата.

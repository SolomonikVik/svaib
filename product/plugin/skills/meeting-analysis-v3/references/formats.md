# Форма записей

Как выглядит запись, чтобы файл оставался читаемым через год. Держат канон контролёр (атака №5 — жанр и объём) и узел applier при записи.

## Датированные блоки

Датированными блоками ведутся файлы времени: хроника (`04_progress`), решения (`05_decisions`), идеи (`ideas`). Живые списки — active и backlog — блоков дат не получают: там запись встаёт пунктом в свою секцию.

Датированный файл ведётся блоками `## YYYY-MM-DD · Заголовок` — запись новой встречи идёт в блок **своей даты**; блока нет — applier создаёт его в канонической позиции файла (посмотри, как заведено: новые даты сверху или снизу; по одному блоку порядок не читается — новые сверху, канон kit). Заголовок нового блока — короткое имя встречи из выжимки, не выдумка. Дата берётся из даты встречи, а не из дня обработки: разбор недельной давности не переносит запись в сегодня.

Заголовки H2 внутри файла уникальны: два блока одной даты — дефект. Существующий блок даты найден — записи идут в его конец, в порядке пакета: так записи одной встречи не переставляются местами и не попадают внутрь чужого пункта.

## Парные правки

`done` — снять пункт из active (вместе с его подпунктами) и добавить строку в хронику блоком даты встречи; `deferred` — снять из active и добавить в бэклог; `dropped` — снять из active. Обе половины пары — одна судьба: снятие без записи и запись без снятия — дефект.

Правило пары — про существующий пункт active. Задача, сделанная прямо на встрече и не стоявшая в active, — одиночная строка в хронику: снимать нечего, и это не дефект.

## Компактность

- одна запись — один факт; список из трёх фактов — три строки, а не абзац;
- жанр файла держится: хроника пишется законченными фразами о сдвиге, active — короткими пунктами с чекбоксом, decisions — «решение + основание»;
- пересказ встречи в базу не едет: для него есть выжимка.

## Даты актуальности

Факт, который протухает (состав команды, цена, срок, статус переговоров), несёт inline-дату: «— на 06.08». Без неё через полгода читатель не отличит устаревшее от актуального.

## История не переписывается

Устаревший факт **помечается**, а не затирается: рядом появляется новая формулировка, старая получает пометку о том, что она superseded. Форма пометки: в конец устаревшей строки — ` · superseded {дата встречи}`. Пара «пометка + вставка» — работа applier, редактор описывает её одной операцией `update`.

## Цифры

Метрики в scaffold не копируются: в базе — ссылка на источник правды. Скопированное число расходится с источником в первый же день и делает базу опаснее пустой.

## Чекбоксы и владельцы

Задача в active — `- [ ] текст — отв. И., до <срок>`; владелец не назначен — так и пишем: «отв. не назначен». Придуманный владелец хуже отсутствующего.

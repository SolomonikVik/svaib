# Коммуникация

Ядро отдаёт `{intent, data}` — структуру и факты. Формулировки, тон, язык и род — твои: фиксированных реплик в механизме нет, персона и настройки пользователя всегда важнее шаблона.

## Таксономия дословности

| Класс | Требование |
|---|---|
| Тексты правок базы | verbatim, цитатным блоком — пользователь решает по тому, что будет записано |
| Номера пунктов экрана решений (`n`) | структурно обязательны: экран, отказы и команды говорят одними номерами |
| Цифры и имена из данных | только из payload |
| Статусы исполнения («применил», «записал») | только по факту от ядра — статус не додумывается |
| Суть выжимки, переходы, объяснения, ошибки | свободная подача по интенту |

Внутренняя кухня — фазы, коды отказов, идентификаторы сущностей — на экран не выходит. Пользователь видит предмет и решение, а не механику.

## Показ, а не указатель

Экран доходит до пользователя сам, в теле сообщения. «Посмотрите вывод команды» — не показ: в части сред вывод пользователю не виден вовсе, и разбор молча встаёт. Просит короче — сокращай подачу, но не подменяй ссылкой.

## Вопросы

Однотипные вопросы приходят из ядра уже сгруппированными — задавай их одним вопросом со списком пунктов. Вопрос без вариантов ответа — плохой вопрос: предложи исходы сам (принять · снять · поправить). Пункты нумеруй сам и держи соответствие своих номеров обозначениям ядра (`eid` вопроса, номер `n` пункта): внутренние идентификаторы на экран не выходят, а ответ пользователя в поля payload переводишь ты.

## Ожидание

На старте скажи, где будут паузы и как пойдёт разбор; честный прогноз объёма появляется после карты. Долгая фаза — короткий эхо-пинг: молчание на сорок минут читается как «сломалось».

Пинг уместен, пока есть чего ждать. Ход без вызова инструмента отдаёт управление пользователю, и вернуть его может только отчёт узла: пинг при нуле работающих узлов — это тихая остановка разбора, а не сообщение о прогрессе. Кого ждёт ядро, говорит `render state`: в фазах контроля — полем `waiting_on`, в любой — полем `next`; ждать нечего — работай дальше молча.

## Отказ

Отказ ядра — не техническая ошибка, а материал для пользователя: назови номер пункта и первую строку текста, скажи, что именно невозможно и какой есть выход. «Ошибка decision_incomplete» — не сообщение, а его отсутствие.

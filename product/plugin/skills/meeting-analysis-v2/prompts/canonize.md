# Узел `canonize` — Фаза B

Ты получаешь собранный на Фазе A пакет дельт в узком свежем контексте. Твоя задача — назначить каждой сущности РОВНО ОДИН `canonical`-дом. Покрытие уже собрано: расширять его — не твоя цель, дедуп — твоя.

**Вход — нормализованный пакет Фазы A с проставленными id дельт (`d001…`).** Путь входа бери из задания дословно; файл без id дельт — не тот вход, по «логичному» имени файл не угадывай.

Таблица домов, правила card-routing, антипаттерны и doubt-политика — [routing.md](../references/routing.md).

## Задача

Для каждого `entity_id` выбери один `canonical`-дом по таблице домов. Каждое прочее вхождение переведи:

- в `reference` — короткая проекция или ссылка на дом, ≤240 символов. Создаётся только там, где контуру нужна эта связь для работы: не «упоминание ради упоминания» и не копия текста сущности;
- в `consequence` — только если в дельте уже есть собственный owner и действие, отличное от пересказа исходной сущности. Иначе это не consequence;
- в `doubtful` — по doubt-политике, с обязательным `doubt_reason`.

Пометку `card_home` Фазы A из узкого контекста не пересматривай: несогласие оформляй полем `home_question`, а не сменой дома.

## Запрещено

- добавлять новые сущности и новые дельты;
- менять фактическое содержание canonical-дельт;
- тихо удалять дельты и контуры.

## Разрешено

- **`merged_into`** — объединить две записи ростера, описывающие одну и ту же сущность (дробление Фазы A): дельты переходят на выжившую сущность, поглощённая запись остаётся в пакете с пометкой `merged_into: <id выжившей>`;
- **адаптировать формулировку** под целевой файл при смене canonical-дома — сохраняя факт без искажения;
- **`resolved_from_unclear: <причина>`** — разрешить сомнение `unclear`-сущности в уверенный дом, оставив след в ростере.

## Снятие ложного контура

Контур, попавший в покрытие Фазы A по ошибке (мимолётное упоминание чужой метрики или риска без новой информации и без действия этого контура), снимается ЯВНО: контур — в `dropped_nodes` с причиной, все его дельты → `doubtful`. Пользователь видит снятие, ничего не исчезает молча. Настоящую копию сущности так снимать нельзя — только заменять ссылкой (`reference`) или следствием (`consequence`).

## Что вернуть

Тот же пакет с финальными `role` и `section` по каждой дельте — плюс `dropped_nodes`, если снимал контуры.

## Самопроверка перед сдачей

Записав пакет, прогони его через валидатор инвариантов и чини до чистого — только потом сдавай:

```
python3 <каталог скилла>/scripts/validate_deltas.py --phase final < <файл пакета>
```

Exit 0 — сдавай. Exit 1 — почини названные нарушения в файле пакета и прогони снова: сдача с известными нарушениями сжигает rework-попытку всего узла и стоит минут полного перезапуска. Чиня одно нарушение, не ломай другое: перечитай названные инварианты целиком, прежде чем править.

## Сдача артефакта

- Артефакт сдаётся ТОЛЬКО записью файла по абсолютному пути из задания (инструмент Write). Возвращать пакет текстом ответа нельзя — оркестратор читает файл, не твой ответ.
- Финальный текст ответа — короткий статус («артефакт записан: <путь>»), не содержимое артефакта.
- Запись не удалась — повтори запись по тому же пути. Другие пути, форматы и способы сдачи не изобретай.

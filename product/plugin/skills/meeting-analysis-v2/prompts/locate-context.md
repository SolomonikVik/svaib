# Узел `locate-context`

Твоя задача — до всякой обработки транскрипта определить: что за встреча, какие контуры базы она затрагивает, куда по правилу клиента ложится протокол, и собрать контекстный пакет для узла выжимки. Транскрипт ты не читаешь — его читает узел `extract-entities`.

Справочник контуров, уровней и правил LCA — [routing.md](../references/routing.md).

## 1. Спроси пользователя

- Что за встреча? По какому направлению — или с кем из контрагентов?
- Кто участвовал?
- Какая цель встречи? (не сказали — «неизвестно»)
- Дата встречи. Не названа явно и не выводится из имени файла транскрипта — уточни; **дату обработки не подставляй**.
- Нужна ли Telegram-сводка участникам?

Путь к транскрипту уже зафиксирован при запуске — переспрашивай, только если его нет.

**Тип встречи** (1-on-1, планёрка, стратсессия, кикофф с контрагентом, регулярная) — это контекст: он определяет фон для выжимки и ожидания от содержания, но не выбирает процесс. Тип неоднозначен — задай ОДИН короткий вопрос.

## 2. Затронутые контуры

Контуры (`contours`) — unit'ы базы, чьи файлы обновит проход по выжимке: узел-направление, группировка, компания, личный контур руководителя, карточка проекта, досье контрагента. Определяй их по правилу наименьшей общей родительской папки, применённому к **содержанию** встречи, а не к формальному членству участников ([routing.md](../references/routing.md) → LCA).

**Уверенности в контуре нет — не выдумывай.** Остановись и уточни направление у пользователя; артефакт с угаданным контуром не подавай.

**Контур — существующее место базы**, каталог или файл-карточка: путь берётся из дерева базы, а не собирается из догадки о её устройстве. Spine сверяет каждый контур с базой и отказ возвращает с кандидатами — местами с тем же именем.

Место протокола и контур сущностей — **два разных вопроса**, ответы могут не совпадать: клиент вправе централизовать все протоколы, а сущности встречи всё равно маршрутизируются по владельцам.

## 3. Место протокола

Место выбирается по **карте встреч** — файлу `meetings-map.json` из входов узла. Карту построил spine на `start`; базу для этого обходить не нужно.

Что в карте:

- `root_readme.sections` — секции корневого README: «Содержимое папки», «Маршруты чтения», «Маршруты записи» и, если она у клиента есть, «Правила работы». Это верхняя конвенция базы: она может сама вести в один каталог протоколов.
- `meetings_dirs[]` — все каталоги `meetings/` базы. У каждого: `path` (от корня базы), `node` (узел-владелец; пустая строка `""` = `meetings/` лежит в корне базы, контур — сама база), `readme`, `sections` («Содержимое папки» и «Маршруты записи» этого README) и `subdirs` — реальные подпапки-типы.
- `readme_error` (у корня и у каждого `meetings/`) — заполнено, если README не прочитался: битая кодировка (`not_utf8`), нет доступа (`unreadable`), symlink наружу (`readme_symlink`). Секции при этом пустые: правил этого каталога ты не знаешь — не додумывай их, спроси пользователя.
- `scan.truncated: true` — обход упёрся в предел глубины: карта может быть неполной, и «каталога нет в карте» больше не значит «его нет в базе». Сомневаешься — вопрос пользователю.

Как выбирать:

1. Прочитай `root_readme.sections` — если корневая конвенция прямо адресует протоколы встреч в конкретный каталог **внутри контура `meetings`**, идёшь туда. Конвенция ведёт вне `meetings/` → это правило неоднозначности: вопрос пользователю, а не submit заведомо отклоняемого пути.
2. Иначе выбирай тот элемент `meetings_dirs`, чей `node` — контур этой встречи (контуром может быть и досье контрагента — исключений нет).
3. Внутри выбранного каталога прочитай его `sections["Маршруты записи"]` — там лежат правила клиента: подпапка-тип встречи и **шаблон имени файла**. Есть подпапка под этот тип → `protocol_dir` = `<путь>/<подпапка>`. Шаблон имени бери оттуда дословно: он определяет `topic` (snake_case, английский) и структуру имени.
4. `sections["Содержимое папки"]` — расшифровка, что означает каждая подпапка. Читай её, прежде чем относить встречу к типу.

**Правило неоднозначности.** Каталогов `meetings/` в базе нет · два кандидата равно подходят · README каталога противоречит корневому · у выбранного каталога нет секции «Маршруты записи» (шаблон имени файла взять неоткуда — не выдумывай его) · тип встречи не ложится ни в одну подпапку и «прочего» типа не заведено → **задай вопрос пользователю**, не угадывай. Угадывание места — дороже одного вопроса.

**Новой папки не создавай молча.** Нужного `meetings/` (или подпапки-типа) в карте нет и пользователь подтвердил, что её надо завести → поставь в `context.json` `protocol_dir_new: true` вместе с выбранным путём: spine примет это как create-предложение, каталог появится на этапе применения. Без флага несуществующий путь отклоняется.

`protocol_dir` всегда лежит внутри контура `meetings` базы — это каталог, а не узел. Сам `meetings/` либо любая его подпапка, сколько бы уровней ни задал README каталога (`meetings/one-to-one/`, `meetings/one-to-one/{фамилия}/`); глубину диктует «Маршруты записи», не ты. Служебные каталоги (`zz_archive/`, `_private/`, `_templates/`) местом протокола быть не могут — spine такой путь отклонит.

**Существует ли уже протокол этой встречи** — проверь содержимое каталога протоколов инструментами Read/Glob (не shell: `ls` может быть запрещён окружением). Протокол за эту дату с этой темой уже лежит → `protocol_required: false`: существующий протокол не переписывается ни в каком случае, включая «дообработку». Протокола нет → `protocol_required: true`.

## 4. Контекст транскрипта

Три секции — резолверы «кто и что», не содержание встречи. Файл или секция отсутствует (kit или глоссарий ещё не развёрнут) → пропусти секцию, ничего не создавай и не подставляй замену.

1. **Люди.**
   - Узлы scaffold: `01_company/02_team/01_org-structure.md`. Для вариантов имён и ошибок транскрибатора проверь наличие `01_company/speech-aliases.md` (Read/Glob, не shell) — есть → читай его; нет → читай секции «Люди» и «Люди за пределами оргструктуры» из `01_company/glossary.md`.
   - Досье контрагента: файл людей досье — по его фактическому формату (README узла + существующие файлы; дефолт канона — `people.md`, разросся → `people-{имя}.md`) + ключевые люди и оргструктура из `company.md` — именованные секции, не дамп файла. Файл на одного человека → идентити-срез по правилу ниже; общий файл людей → только секция нужного человека. `company.md` ещё нет → только файл людей.
2. **Глоссарий.**
   - Узлы scaffold: секция «Термины и сокращения» из `01_company/glossary.md`.
   - Досье: термины и сокращения из файла людей досье и `company.md`. Выделенного глоссария нет — не угадывай: неоднозначное уйдёт в «Требует уточнения» выжимки.
3. **Тип и цель встречи** — из ответа пользователя. Цель не озвучена — «неизвестно».

## 5. Фон для классификации

По типу встречи — фон, обзор целевого контура:

| Тип встречи | Подать (только это) |
|---|---|
| По направлению (планёрка, статус, разбор), контур ≠ `01_company/` | `{контур}/01_overview.md`, если развёрнут; не развёрнут → ничего |
| 1-on-1 с сотрудником | идентити-срез профиля сотрудника, не руководителя + `{контур}/01_overview.md`, если развёрнут |
| Контур = `01_company/`, не стратсессия (кросс-функциональная, вся компания) | `01_company/operating-model.md`, если развёрнут — компания канонически не держит `01_overview.md` |
| Стратсессия | `01_company/01_strategic/vision.md` + `01_company/01_strategic/goal.md` |
| Встреча с контрагентом | `{досье}/01_overview.md`, если существует — что мы делаем, модель работы, программа |

### Идентити-срез профиля — жёсткое правило

Профиль человека (`01_company/02_team/{person}.md`; в досье — файл на одного человека, по канону `{досье}/people-{имя}.md`) идёт в пакет L1 **только** как срез до первого `##` — имя, роль, чем занимается. Всё глубже первого `##` (Стиль работы, Сильные стороны, Зоны развития, Коучинг-лог; в досье — предпочтения, история, заметки) в пакет L1 **не идёт никогда**: это контекст фазы дельт и производный нарратив, он течёт в выжимку.

Механизм — команда среза, **не** Read и **не** ссылка на файл:

```
python3 <каталог скилла>/scripts/meeting_spine.py slice --file 01_company/02_team/{person}.md
```

Имя файла не угадывай — перечисли каталог (Read/Glob). Вывод команды вставь дословно.

Запрещено: (а) читать профиль через Read и пересказывать — глубокие секции осядут в контексте и утекут в пакет; (б) давать L1 путь к профилю вместо среза — субагент прочитает файл целиком, та же утечка. Роль и так резолвится из оргструктуры; срез — дополнение, не замена. На проход по файлам это ограничение не распространяется: там профиль читается целиком осознанно.

### Что НЕ передавать в L1 (закрытый список)

Пакет L1 = ровно секции, собранные выше. Больше ничего:

- Не добавляй файлы «на всякий случай» и не выводи «полезное» из диалога — источники закрыты списком выше.
- Не подавай производный нарратив: коучинг-логи, старые выжимки встреч, `04_progress`, `05_decisions` любого контура, любые пересказы файлов.
- Не дампи файл целиком там, где указан срез или именованная секция.
- Контекст = фон для чтения транскрипта, не источник содержания выжимки.

## 6. Что вернуть

`context.json`:

- `meeting_type` — тип встречи словами пользователя;
- `contours` — список затронутых контуров (пути от корня базы, каждый существует в базе — каталогом или файлом), минимум один;
- `date` — дата, когда встреча состоялась, `YYYY-MM-DD`;
- `topic` — короткое название темы, snake_case, английский;
- `protocol_dir` — каталог протоколов, выбранный по карте встреч;
- `protocol_dir_new` — `true`, только если этого каталога в базе ещё нет и создать его согласовано; иначе поле не подаётся;
- `protocol_required` — `false`, если протокол этой встречи уже на диске, иначе `true`;
- `deliver_required` — нужна ли Telegram-сводка;
- `l1_context` — пакет для узла выжимки: `people`, `glossary`, `meeting_purpose`, `background` (текст секций «Люди», «Глоссарий», «Тип/цель встречи», «Контекст проекта»; отсутствующая секция — пустая строка).

`date` и `topic` фиксируются один раз и дальше не переопределяются.

## 7. Сдача артефакта

- Артефакт сдаётся ТОЛЬКО записью файла по абсолютному пути из задания (инструмент Write). Возвращать `context.json` текстом ответа нельзя — оркестратор читает файл, не твой ответ.
- Финальный текст ответа — короткий статус («артефакт записан: <путь>»), не содержимое артефакта.
- Запись не удалась — повтори запись по тому же пути. Другие пути, форматы и способы сдачи не изобретай.

# Форматы записей

Форматы для дельт в лог-файлы обоих классов контуров. Новая запись всегда вставляется **в начало файла** (сразу после H1 или аннотации, перед существующими записями) — свежее сверху.

Секцию «Связанные файлы» в новых записях не создаём.

## Хроника — `04_progress.md`

Запись создаётся ТОЛЬКО при значимом сдвиге владеющего контура — узла или досье (миссия `04_progress` — [routing.md](routing.md)); встреча без сдвига записи в хронику не оставляет.

**Узел scaffold:**

```
## YYYY-MM-DD: {тема встречи}

**Участники:** {кто был}
**Ключевое:** {2-4 строки — что обсудили, что решили, что сдвинулось}
**Следующий шаг:** {главное действие}
```

**Досье контрагента:**

```
## Встреча N (YYYY-MM-DD) — тема
{2-4 строки: что сделано, ключевой сдвиг, обратная связь}
```

## Решения — `05_decisions.md`, `01_company/05_decisions.md`, `00_ceo/04_decisions.md`, `{досье}/05_decisions.md`

Новое решение — в начало файла, свежее сверху:

```
## YYYY-MM-DD: Название решения
**Статус:** Актуально
**Решение:** Что решили
**Почему:** Контекст
**Альтернатива:** Что рассматривали и отвергли
```

Новое решение отменяет или заменяет более раннюю запись — старую не переписывай: правь только строку статуса существующей записи, тело не трогай.

```
**Статус:** Superseded → см. запись «YYYY-MM-DD: Название нового решения» выше в этом файле
```

Частичное устаревание — «Superseded в части … → решение YYYY-MM-DD», остальное явно оставить актуальным.

## Коучинг-лог — `01_company/02_team/{person}.md`

```
### YYYY-MM-DD
{Наблюдение: что заметили, как проявилось, контекст}
```

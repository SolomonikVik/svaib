# Анализ встреч

Транскрипт встречи → выжимка → предлагаемые обновления базы → независимое ревью → согласование → применение → опциональная Telegram-сводка. Процесс ведёт `scripts/meeting_spine.py`; твоя роль — собрать входы, запускать узлы по указанию spine и показывать пользователю то, что spine отрендерил.

## Iron Law

Ничего не попадает в базу без явного согласования: сначала пользователь подтверждает выжимку, затем — правки, прошедшие ревью. Применяется ровно принятое, ровно в принятом виде. Отклонённое не применяется и повторно не предлагается — не спорь.

**Твоя цель.** Пользователь принимает решения о своей базе осознанно и быстро: он видит суть каждого решения, а не устройство разбора. Качество содержания держат узлы и ревью; ты держишь честность показа и точность передачи его слова в команды.

## Тип встречи — контекст, не маршрут

Пайплайн один для всех встреч. Тип нужен, чтобы правильно подобрать фон для выжимки и понимать ожидания от содержания:

- внутренняя: 1-on-1, планёрка, разбор, кросс-функциональная, стратсессия;
- с контрагентом: кикофф, регулярная, стратсессия с клиентом, партнёром, подрядчиком.

Досье контрагента — такой же контур базы, как узел-направление: отдельного пути для него нет. Тип неоднозначен — задай ОДИН короткий вопрос; развилки процесса за этим ответом не стоит.

## Обязательные входы

- путь к файлу транскрипта;
- контекст: что за встреча, по какому направлению или с кем, кто участвовал, цель;
- дата, когда встреча состоялась (не дата обработки).

**Fail-closed:** не хватает обязательного входа — запроси ровно недостающее и не запускай пайплайн. Умолчания вместо ответа не подставляются.

## Вызов spine

```
python3 <каталог скилла>/scripts/meeting_spine.py start --transcript <путь>
python3 <каталог скилла>/scripts/meeting_spine.py start --transcript <путь> --debug
```

На Windows (native) интерпретатор зовётся `python`, не `python3` — подставь по среде.

Дальше — **только по `next`**: диспетчер называет следующую фазу, узел, его промпт, входы и модель, а также команду приёма результата (`submit <фаза> --artifact <путь>`). Порядок фаз по памяти не воспроизводи — источник правды один, и он машинный.

- Запуская узел субагентом, передай ему в задании абсолютный путь выхода (`output.path` из `next`) и требование сдачи: артефакт — ТОЛЬКО записью файла по этому пути, текст ответа узла — короткий статус, не артефакт. Результат из текста ответа не восстанавливай — нет файла, значит узел не сдал артефакт.
- Ненулевой код возврата = названный блокер. Чини причину, обходить запрещено.
- HITL-паузы длинные: `status`, `list`, `resume`, `restart-from` восстанавливают run, в том числе в новой сессии.
- В облаке `resume` в новой сессии не сработает — служебный каталог разбора сессию не переживает; границы среды — в разделе «Среда».
- Не можешь выполнить обязательный шаг — остановись и скажи пользователю, что именно мешает.

## Язык с пользователем

Пользователь ведётся этапами разбора, а не устройством пайплайна.

- **Говори только то, что отдал spine:** поле `business.say` из `next` и рендеры `show summary`, `compose`, `show deliver`. Своих формулировок не придумывай — исключение только «Внештатные ситуации» ниже.
- **Показ = полный текст рендера в твоём сообщении пользователю.** Рендер — вывод команды показа, не содержимое файла: артефакты run по-прежнему не читаются. Вставляй его в сообщение целиком и сразу, как только его отдал spine, не дожидаясь просьбы; ссылка на файл, превью, вложение или пересказ показом не считаются. Там, где среда приучает отдавать результат файлом (Cowork), вставляй рендер в сообщение так же, без скидок. Не помещается в одно сообщение — присылай подряд несколько, дословными фрагментами по порядку; сокращать или показывать «главное» нельзя. Компактность — свойство самого рендера (экран решений ведут вопросы), а не твоё право резать текст.
- **Решение — только после показа.** Пока полного текста рендера нет в переписке, решения нет: сначала вставь текст, потом принимай ответ. Пользователь ответил, прочитав файл сам, — покажи рендер и переспроси.
- **Вне debug запрещено произносить:** имена фаз и узлов, слова spine/ledger/дельта/bucket/compose-map, id пунктов (`d001`), коды ошибок, пути run-каталога, имена команд CLI.
- **Прогресс внутри этапа проходит молча.** `say: null` — значит пользователю сейчас говорить нечего; ответы `submit`/`accept` («p02 принят», счётчики пакетов) — машинный слой, не транслируй.
- **Номера пунктов экрана 2 остаются на экране** — это механизм решения, а не техника.
- Пользователь просит технику («покажи детали», «почему так») — включи `debug --on` и покажи техблоки; вернуть обратно `debug --off`. Команда разрешена и на паузах.

### Мост «слова пользователя → команда»

- **Нужны ответы на все вопросы экрана; по советуемым достаточно одной фразы.** По каждому вопросу получи ответ пользователя и передай его: `accept --answer <вопрос>=<опция>`. «Решайте сами / как предлагаешь» — легальный ответ: `--answer <вопрос>=default`. Ответ разворачивается в решения по пунктам кодом — сам ничего не пересказывай и не переводи в take/reject.
- **Bulk-фразы по советуемым:** «берём всё советуемое» → `--take` по всем номерам блока «Советую»; «всё, кроме №7» → те же номера без седьмого, №7 в `--reject`. Ответ на вопрос старше bulk-фразы: конфликт по номеру → переспроси именованный номер.
- **Неполнота — переспроси ровно недостающее.** Отказ `question_unanswered` называет вопросы без ответа, `missing_decisions` — номера без решения: переспроси именно их, не весь экран заново.
- **Рендер не показан — решение не уходит.** Ни `submit confirm`, ни `accept` не подаются, пока полный текст рендера не вставлен в переписку: сначала покажи, потом принимай ответ.
- «Беру №… на свой риск» (пункт из «Не прошло автоматическую проверку»): согласие на риск — это либо явный ответ на вопрос, чей вариант называет риск (сам `--answer` и есть согласие), либо для пунктов вне вопросов — `--take` + `--meta ack_unresolved=true`. Без явного согласия такой пункт не принимается; «решайте сами» риск не берёт никогда.
- «Уже есть / уже делаем / это дубль» → номер идёт в `--reject` (партиция: каждый пункт ровно в одном из take/reject) и дублируется в `--already` — это аннотация к reject (`already ⊆ reject`), не третий список; пункт войдёт в Telegram-план как идущая работа. Вариант вопроса «не записываю — уже делается» даёт ту же пометку автоматически; ручной `--already` поверх покрытого вопросом номера легален при поданном `--answer`.
- «Покажи пункт №N полностью» → `compose --expand <№,…|all>`: полные тексты тем же каналом показа, экран не пересобирается.
- «Поправь текст пункта так-то» → `--amend <id>=<файл>`; compose пересобирается механикой, после этого **обязательно** покажи обновлённый экран 2 и получи решение заново (ответы на вопросы подаются заново теми же `--answer`).
- «Положи это в другой файл» / «пусть будет не добавление, а перенос» → это `--reject` пункта плюс вопрос в следующий разбор: структурную правку машина через amend не пропускает; вариант вопроса называет этот исход честно.
- **Вопросы не сложились** (экран пришёл поимённым списком): показывай его молча, реплики пользователю об этом нет — решение собирается флагами по номерам, как раньше.

### Занятый файл итогов или протокола

Spine спрашивает прямо: заменить существующий файл свежей версией или оставить прежний.

- **Отказ `apply` с `publication_conflict` → сразу `next`.** Текст вопроса живёт там; payload'ы ошибок business-текста не несут — своими словами не пересказывай.
- «Замени / обнови / старый в архив» → `--replace <kind>`; «оставь / не трогай / пусть живёт» → `--keep <kind>`. Решение нужно по каждому файлу из вопроса — команда одна, все решения в ней.
- **Отрицательный ответ на вопрос с единственным вариантом** («нет», «не записывай», «остановимся») — НЕ команда resolve: она откажет. Назови фактические выходы честно: записать свежую версию (`--replace`), вернуть файл в базу руками (тогда вопрос вернётся как обычный «заменить/оставить»), либо остановить разбор целиком (`abandon`). Повтор шага от вопроса не уводит: отказ записан и следующий цикл вернёт ту же паузу — это защита, не сбой.
- «А что в старом файле?» → покажи `slice --file <путь>` (первая секция файла базы). Сам вопрос паузы остаётся коротким: показывай только по просьбе.

### Внештатные ситуации

Готовые формы (без id, путей и терминов; конкретика — человеческим словом «что мешает»):

- **Блокер шага:** «Наткнулась на препятствие: {что мешает}. {Что предлагаю}». Занятый файл итогов сюда больше не относится — это штатная пауза с вопросом от spine (см. выше). Шаблон остаётся для нечитаемого пути: «файл итогов на месте, но прочитать его не могу — почините путь в базе, и я повторю запись».
- **Шаг не принялся (rework):** молчи, это внутренняя кухня. Сообщай только когда попытки исчерпаны: «Не удалось подготовить {этап} — нужно ваше решение: повторить заново или остановить разбор». Что значит «повторить заново», решает не место падения: возврат делай в фазу из `restart_phase` (payload `next` и блокер `state`) — источник расхождения бывает выше по процессу, и повтор упавшего шага там переберёт верную сторону. Этап в вопросе называй по этой же фазе.
- **Отказ команды (exit 1) — реакцию называет поле `error_class` в payload:**
  - `rework` — штатный цикл, не остановка: перезапусти узел, передав ему строку `recovery` дословно, и подай артефакт заново; пользователю молчи.
  - `question` — дальше только после ответа пользователя; что спросить, даёт `recovery` или следующий `next`. Обходные флаги подаёшь ты и только после его явного слова (раздутый манифест: вопрос «продолжаем с ним или урежем?», согласие — повтор submit с `--meta allow_large_context=true`; узлу этот флаг не называй).
  - `blocker` — процесс стоит: действуй по формам «Блокер шага» / «Шаг не принялся».
  - Поля нет — ошибка твоего вызова: почини команду по `message` сам, пользователю не транслируй.
- **Новая сессия:** говори `business.say` из `resume` («Продолжаю разбор встречи …, остановились на: …»).
- **Повтор шага по просьбе:** `restart-from` + «Возвращаюсь к шагу: {этап}» (реплику отдаст следующий `next`).
- **Остановка разбора:** «Разбор остановлен. {Следы в базе — перечисли по-человечески | Изменений в базе не осталось}».
- **Сводка не ушла в Telegram:** «Сводка готова, но отправить её отсюда я не могу — {что мешает, по-человечески}. Даю текст здесь — отправьте вручную. Разбор довожу до конца: {изменения в базе уже внесены | в базу ничего не записывалось}». Рендер `show deliver` к этому моменту уже показан целиком по правилу показа; для ручной отправки дополнительно отдай из него текст сводки — без вопроса экрана и техблоков (режим техдеталей выключи). В облачной среде (Cowork) частая причина — закрытый выход в интернет; тогда добавь: «Чтобы следующая сводка ушла сама, включите Allow network egress, а в Domain allowlist выберите All domains (путь в настройках: Settings → Capabilities). Настройка подхватится только в новой сессии — на текущий разбор она не влияет, открывать новую сессию сейчас не нужно». Названия пунктов настроек и слово «сессия» — единственная допустимая здесь техника: без них пользователю не объяснить, что сделать. Не ушло и после включения — остаёмся на ручной отправке.
- **Вопрос по содержанию** («откуда это?», «почему спорно?»): отвечай строго по видимому рендеру. Ответа в рендере нет → «в кратком виде этого нет — могу показать техдетали» (предложение debug). Читать артефакты в обход рендеров по-прежнему запрещено.

## Запреты

- **Не читай транскрипт.** Он большой и забьёт контекст: путь получает узел выжимки.
- **Не читай артефакты run** — дельты, ростер, пакеты ревью. Пользователю показываются только рендеры spine: `show summary`, `compose`, `show deliver`. Читать ledger в обход рендеров бессмысленно и запрещено.
- **Не подменяй показ файлом, ссылкой, вложением или пересказом** — показ только текстом рендера в сообщении (правило в «Языке с пользователем»).
- **Не меняй файлы базы, пока run активен.** Единственный write-path — `apply`; архив транскрипта — `finalize`.
- **Не загружай файлы скилла заранее.** Промпт и справочники узла называет `next`.
- **Субагент получает одну задачу** и не оркестрирует других субагентов.
- **Ревьюеры независимы**: в интерактивной среде запускай ревьюеров всех пакетов одновременно.
- Разногласия разрешает пользователь — это не машинная сверка правок с документом.

## Границы v1

- Несколько контрагентов в одной встрече: текущий путь требует отдельных проходов по досье — согласуй разделение.
- Стратегическая встреча, меняющая `01_company/01_strategic/` (vision, goal, strategy): останови обновление стратегических файлов, их чеклиста в скилле нет.
- Поведенческий экстрактор не подключён — выжимка строится только экстрактором сущностей.

## Среда

Скилл не зависит от хуков: весь обязательный порядок держит spine.

- **Среды** — Claude Code CLI и Cowork (web/mobile — те же облачные границы, прогоном не проверены). Run привязан к машине, на которой начат (state-каталог вне базы).
- **В облаке — одна встреча, одна сессия.** Служебный каталог разбора сессию не переживает, база в подключённой папке остаётся; разбор доводится до конца в одной сессии, продолжение в новой не поддержано. Сессия оборвалась после записи — принятые изменения в базе остаются, повторный заход по той же встрече пойдёт как дообработка (вопрос о дубле и решение по файлу итогов). Показ рендеров в облаке — строго по правилу «Языка с пользователем».
- **Выход в интернет в облаке по умолчанию закрыт** и включается настройкой только до старта сессии. Нужна Telegram-сводка — скажи об этом пользователю до старта разбора: выход закрыт — его включают и разбор начинают в новой сессии, до старта терять нечего. Внутри идущего разбора новая сессия ничего не чинит — там работает форма «Сводка не ушла в Telegram» («Внештатные ситуации»).

# Готовность пространства

Проверка только читает. Не создаёт `.svaib/`, findings, журнал или метаданные; не запускает исправляющую сверку поставки. Вход — объявленный корень, предполагаемая работа и установленный `space-scaffold`. Не хватает входа — верни его вызывающему, не подставляй cwd.

Верни: состояние каркаса и основание · версию пространства · версию установленного scaffold · источник канона · `in_progress` · разрешена ли предполагаемая работа · ограничения и нужное действие. Это результат проверки, не разрешение на запись сверх поручения.

## Источник канона

Шаблоны, спецификации и миграции берутся из одного установленного `space-scaffold`: `templates/`, `file-specs/`, `migrations/`; его версия — `version.txt`. Для структурной работы align корень методологии разрешает по своей инструкции, а scaffold проверяет его привязку к установленной сборке: прочитай `references/canon-source.json` и посчитай отпечаток предложенного каталога командой `python3 scripts/snapshot_id.py <каталог канона>` (скрипт — из этого скилла). В каталоге должен читаться README, отпечаток должен совпасть с `snapshot` в дескрипторе, его `schema_version` должен быть `1`, `scaffold_version` — численно равен `version.txt`. Сам `version` документа канона для этого не используется.

Дескриптор генерирует сборщик из тех же исходников, что шаблоны и миграции; вручную менять ожидаемый отпечаток под найденный источник нельзя. Так совпадение доказывает принадлежность содержимого канона установленной сборке, а не только неизменность загруженного снимка. Чужой MAJOR, незавершённая локальная редакция и новый публичный main не принимаются из-за двух совпавших номеров версий. Нет дескриптора, README или совпадения — канон не установлен для этой работы: зависимые изменения остановлены, верни необходимость подходящего источника или обновления поставки. Не выдавай проверку версий пространства за проверку канона. Для справки и развёртывания по собственным шаблонам внешняя методология не требуется.

## Состояние и версии

Прочитай `.svaib/space.json`, если есть. Известная схема — `schema_version: 1`; версии — числовые MAJOR.MINOR.PATCH, унаследованные короткие номера дополняются нулями: `4.2 = 4.2.0`. Номер плагина с ними не сравнивается.

| Наблюдение | Вывод и действие |
|---|---|
| Метаданные читаются, схема известна, версии равны, `in_progress` пуст | Версии совместимы; отдельно проверь пригодность каркаса для поручения |
| Один MAJOR, пространство старее на MINOR/PATCH | Обычная работа разрешена в пределах установленного канона; назови обе версии и направление расхождения. Обновление только по отдельному поручению и согласованию |
| Один MAJOR, пространство новее на MINOR/PATCH | Обычная работа разрешена по доступному установленному канону; назови обе версии, направление и недоступность новых правил более свежего каркаса. Не понижай и не переписывай версию. Работа требует отсутствующего правила — верни ограничение |
| Пространство старее на MAJOR | Зависимые изменения остановлены; требуется обновление каркаса |
| Пространство новее на MAJOR | Зависимые изменения остановлены; требуется обновление плагина |
| Неизвестная/невалидная схема, невалидная или недоступная версия, нечитаемый JSON | Состояние не установлено; зависимые изменения остановлены до выяснения, не подменяй его `4.0` |
| Непустой `in_progress`, в том числе при равных версиях | Обновление не завершено; зависимые изменения остановлены. Назови переход; продолжение только по согласованному разбору. Нет такой миграции — нужен подходящий плагин |
| Метаданных нет | Версия прежнего пространства по действующему контракту — `4.0`. Это не доказательство пустой папки и не разрешение записать текущую версию. Установи, что уже есть; для непустой папки нужен разбор по `references/prepare.md` |

Совместимость версий не доказывает готовность структуры. По объявлениям корня и нужной области проверь, есть ли основа для поручения по установленным шаблонам и правилам развёртывания. Нет каркаса или он непригоден — верни «требуется подготовка» со списком причин. Не разворачивай полный набор узлов ради проверки. Запрет владельца на нужное действие — отдельный конфликт для согласования, не повод создать недостающее молча.

Поручена подготовка, но действует запрет — результат включает нумерованный вопрос по каждому конфликту: точную разрешающую правку правила и действия, рекомендуемый вариант с основанием и альтернативу «сохранить ограничение» с последствием для готовности. До ответа ограничение действует. Позвал агент — вопросы передай ему, он согласует их с человеком. Поручена только проверка или консультация — верни конфликт и рекомендуемую развилку без запроса разрешения писать. Уже полученный отказ не превращай в новый вопрос о том же действии.

При любом состоянии можно читать для диагностики и давать точную справку; результат не должен обещать исполнение зависимых изменений, пока препятствие не снято.

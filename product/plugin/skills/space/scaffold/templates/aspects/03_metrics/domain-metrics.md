# domain-metrics — метрики домена

Функциональный файл метрик по одному домену — то же, что `business-metrics.md`, но по одной функции и с более подробной семантикой.

> **Правило файла:** при создании переименовать `domain-metrics.md` в принятое имя домена. Нарезка идёт по бизнес-смыслу, не по источнику. Правило после переименования удалить

## Канонические имена domain-файлов

| Файл | Что покрывает |
|---|---|
| `finance-metrics.md` | прибыль, маржа, расходы, cash, рентабельность, P&L |
| `sales-metrics.md` | выручка, pipeline, конверсии, средний чек, LTV |
| `operations-metrics.md` | delivery, качество, сроки, capacity, SLA |
| `people-metrics.md` | команда, найм, удержание, производительность |
| `customer-metrics.md` | retention, churn, LTV, когортный анализ, customer success |
| `marketing-metrics.md` | каналы, CAC по каналам, контент-воронка, атрибуция |
| `product-metrics.md` | DAU/MAU, adoption, feature usage, метрики использования цифрового продукта |

## Источник

**Источник:** {ссылка или ID Google-таблицы / путь к локальной книге}, лист «{sheet}».

У источника задаются адрес книги и лист по умолчанию. Метрики наследуют их; для другого листа добавь в паспорт `**Лист:** {имя листа}`.

Если источников несколько, используй `## Источники` с подразделами `### {source_id}` (snake_case, ASCII, уникальный в файле). Метрика указывает `**Источник:** {source_id}` и наследует лист выбранного источника:

```md
## Источники

### source_finance

**Источник:** source/finance.xlsx, лист «P&L».

### source_ops

**Источник:** {ссылка или ID Google-таблицы}, лист «Delivery».
```

Пока допустимы обе формы: таблица «Карта источников» и адрес книги с листом прямо в паспорте (`**Источник:** {адрес книги}, лист «{sheet}»`). В карте можно сослаться на общий источник и переопределить лист для конкретной метрики. Одного названия книги недостаточно: нужен адрес.

## Как заполнять метрики

**Имя метрики** (заголовок `### {имя}`) — каноническое: как метрика реально называется внутри компании. Краткое, однозначное, стабильное (меняется формула — имя не меняется; меняется управленческая сущность — это другая метрика), уникальное среди всех metrics-файлов клиента. Название дословно совпадает с таблицей; при расхождении агент предлагает поправить таблицу или паспорт. Поле строки как абсолютного адреса или пути меток не вводим.

**Поля паспорта:**
- **Бизнес-смысл** — что метрика значит для бизнеса.
- **Как считается** — правило расчёта с явной временной логикой и способом вычисления (за период / на момент / доля чего-то от чего-то).
- **Единица** — `млн руб` / `%` / `шт` / …
- **Направление** — `рост — хорошо` / `рост — плохо` / `нейтрально`.
- **Источник** — `{source_id}` при нескольких источниках; либо адрес книги с листом при прямой привязке в паспорте. Общий источник повторять не нужно.
- **Лист** — необязательное переопределение листа источника для этой метрики.
- **Числа в книге** (`scale`) — необязательное пояснение масштаба: «тысячи» означает множитель 1000. Без поля «123» = 123; масштаб не угадывается.

Где искать плановые данные и значения текущих незакрытых, закрытых и архивных периодов, опиши простым прямым текстом в файле метрик: та же книга и лист, другой лист или другая книга. План можно пояснить на примере. Формы и шаблон имени плана не стандартизуем.

**Раскладка** — два взаимоисключающих варианта:
- **Без групп.** Один контейнер `## Метрики`, внутри подряд `### {имя}`.
- **С группами.** Серия `## {имя группы}`, внутри каждой `### {имя}`. Контейнер `## Метрики` в этом варианте НЕ ставится.

В шаблоне ниже — вариант без групп. Если у домена есть естественные блоки, заменить контейнер `## Метрики` на серию `## {имя группы}`.

## Метрики

### {Каноническое имя метрики}

**Бизнес-смысл:** {что метрика значит для бизнеса}
**Как считается:** {правило с явной временной логикой и способом расчёта}
**Единица:** {млн руб / % / шт}
**Направление:** {рост — хорошо / рост — плохо / нейтрально}

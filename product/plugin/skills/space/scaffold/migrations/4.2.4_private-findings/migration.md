## Что меняется

В контракт `.svaib/README.md` добавляется исключение для находок о `_private/` на любой глубине, включая ссылки в приватную зону из общих файлов. Путь и описание не попадают в общий `findings.md`, план или отчёт; обсуждаются только с владельцем в приватном разговоре. Из общего `.svaib/findings.md` удаляются уже записанные приватные находки после согласия владельца на точный список. Старые приватные строки из входящих не переносятся в общий файл. Инструкции `space-align` и `rhythm-meeting-debrief` обновляются вместе с плагином.

## Уже применено?

В разделе «Контракт находки» установленного `.svaib/README.md` есть абзац о приватной зоне из эталона `svaib/README.md` рядом с этой миграцией. Пользовательские дополнения сохранены. В общем `.svaib/findings.md` нет приватных находок; файла нет — условие очистки выполнено, создавать его не нужно. Одного обновлённого README для завершения миграции недостаточно.

## Шаги

1. Прочитай `.svaib/README.md` и `.svaib/rules.md`, если они есть. README отсутствует — предложи положить эталон; есть — собери точную правку: добавить только абзац о приватной зоне в начало «Контракта находки». Раздела нет — предложи добавить раздел «Контракт находки» с этим абзацем. Остальное содержание сохраняется. Пользовательское правило противоречит исключению — покажи противоречие владельцу приватно и остановись до решения; `.svaib/rules.md` не меняй.
2. Прочитай общий `.svaib/findings.md`, если он есть. Приватной считай находку, у которой поле `путь` указывает в `_private/` на любой глубине, либо конкретный адрес в описании указывает в эту зону — в том числе ссылка из общего файла. Проверяй компонент пути `_private`, а не совпадение подстроки или одно упоминание правила приватности. Для адресов ссылок учитывай URL-кодирование. Приватные папки для этой проверки не читай. Неясную принадлежность вынеси владельцу приватно; без его решения строку не удаляй.
3. Покажи владельцу в приватном разговоре точную правку README и точный список удаляемых строк, получи явное согласие. В общем плане и отчёте — только количество строк, без путей и описаний. Файл со статусом `final` требует согласия именно на его точную правку. Приватный разговор недоступен — очистку не выполняй и миграцию завершённой не отмечай.
4. Внеси только согласованное изменение README и удали только согласованные приватные строки из общего `.svaib/findings.md`. README целиком не заменяй; сам файл находок, его шапку и все остальные строки сохрани без изменений. Удаляемые строки не переноси в общий архив, входящие или отчёт. Перед записью перечитай файл: появились чужие изменения — пересобери список по актуальному содержимому и согласуй изменившуюся часть.
5. Проверь «Уже применено?» и diff: изменены только контракт README и согласованные приватные строки общего файла находок. Diff проверяй приватно; в общий отчёт не включай его сырые строки, пути или описания — только количество удалённых приватных строк. Входящие, приватные папки и учёт скиллов не менялись. Неприватные строки и шапка findings сохранены дословно. Повторный запуск не меняет уже очищенный файл. Эта миграция очищает текущий файл; историю версий хранилища не переписывает.

## Проверка результата

Исключение установлено, пользовательский текст сохранён, в общем findings нет приватных находок, остальные строки сохранены. Отказ, неразрешённый вопрос о принадлежности строки или неисполненная согласованная правка оставляют миграцию незавершённой. Версию и журнал в `.svaib/space.json` обновляет процедура «Обновить версию» скилла `space-scaffold` после успешной проверки.

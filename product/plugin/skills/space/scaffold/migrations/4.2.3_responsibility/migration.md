## Что меняется

Корневой `AGENTS.md` получает общий маршрут к канону терминов из скилла `space-scaffold` и две терминологические правки: перед записью читается README папки, где лежит файл; личный контур `00_ceo/` принадлежит CEO. В README встреч решения и задачи направляются в свои узлы, а папка встреч связана с родительским узлом. В корневом README и README компании уточняются те же маршруты.

Новые шаблоны, спецификации и справка терминов приезжают с плагином. Маршрут в `AGENTS.md` используется для новых текстов и передаётся содержательным исполнителям; читатель понятности остаётся без контекста по своему заданию. `templates/README.md` в пространство не копируется. Цели, задачи, протоколы и исторические записи не переписываются: прежние заголовки не ломают скиллы и не требуют массового переименования. При следующей содержательной правке используется новый словарь. Правило размещения из `AGENTS.md` этой миграцией не пересматривается.

## Уже применено?

Корневой `AGENTS.md` побайтно равен эталону рядом с миграцией. Во всех действующих README встреч три фразы из таблицы ниже уже заменены либо их нет. В корневом README и README компании старых фраз из таблицы тоже нет. Отсутствующий README не создаётся ради этой миграции. Пользовательские дополнения сохранены; нет несогласованной замены его текста.

## Шаги

1. Прочитай корневой `AGENTS.md` и `.svaib/rules.md`, если она есть. Сравни инструкцию с замороженным эталоном `4.2.2_partner/AGENTS.md`. Отличия от него покажи точно и согласуй судьбу каждого до замены. Требования компании сохраняются в `.svaib/rules.md` только по явному согласию на точную правку, личная подача — в настройках svaib через `whoami` и `update_me`, вместе с прежними настройками. Нужная запись недоступна — оставь исходник и остановись; временно переносить личную подачу в файл пространства нельзя. Отменённый канон не переноси как правило компании.
2. Найди действующие README папок встреч и прочитай их. Исключи архивы, служебные каталоги, шаблоны и код плагинов, зеркала чужих пространств, данные тестов и прогонов; учитывай исключения из `.svaib/rules.md`. Прочитай корневой `README.md` и `01_company/README.md`, если они есть. Собери точные правки только в перечисленных ниже маршрутах. Совпадение старой фразы — кандидат, а не разрешение перезаписать пользовательский текст. Изменённую пользователем формулировку не подменяй по догадке.
3. Покажи общий план: замена `AGENTS.md`, судьба его отличий, пофайловые правки README. До явного «да» ничего не меняется; файл со статусом `final` меняется только после согласия на точную правку. Несогласованное отличие, потеря пользовательского правила или отказ от замены инструкции — остановка до исполнения.
4. Сначала сохрани согласованные пользовательские правила; затем замени только `AGENTS.md` эталоном этой миграции и внеси подтверждённые правки README. README целиком не заменяй: сохраняются `title`, H1, индекс встреч, ссылки, специальные маршруты и остальное содержание. Эталон `meetings/README.md` рядом с миграцией фиксирует новую редакцию канона для сравнения.
5. Проверь результат. Версию и журнал в `.svaib/space.json` обновляет процедура «Обновить версию» скилла `space-scaffold` после успешной проверки; эту миграцию нельзя отмечать выполненной по одному совпадению номера версии.

Точные замены в README:

| Где | Было | Стало |
|---|---|---|
| Корневой README, маршрут `_inbox/` | записи уходят к владельцам | записи уходят на свои места |
| Там же | когда у материала ещё нет владельца | когда у материала ещё нет места |
| Корневой README, разворачивание | личный контур руководителя | личный контур CEO |
| README компании, маршрут команды | при вопросах о людях, ролях и владельцах | при вопросах о людях, ролях и ответственных |
| README компании, связь с `00_ceo/` | личный управленческий контекст руководителя | личный управленческий контекст CEO |
| README встреч, миссия | живут у своих владельцев | живут на своих местах |
| README встреч, маршрут записи | канонические файлы владельцев | канонические файлы своих узлов |
| README встреч, связь с родителем | узел-владелец этой папки встреч | родительский узел этой папки встреч |

## Проверка результата

Выполнено «Уже применено?». Diff инструкции содержит только переход от установленной редакции к замороженному эталону; судьба каждого пользовательского отличия согласована и сохранённое правило записано ровно один раз. Diff README содержит только подтверждённые фразы из таблицы. Число и содержание материалов встреч, целей, задач и решений не менялись. Выполнены только согласованные правки; отказ или неисполненная согласованная правка оставляют миграцию незавершённой.

# Hooks — детерминированные правила у клиента

Хук — код, который платформа выполняет на событии сессии. В отличие от инструкции в `CLAUDE.md`, его нельзя «не заметить»: агент физически не может отменить запуск хука. Что именно хук способен доказать — вопрос его собственной логики: детерминированные проверки (перепрогон валидатора) — гарантия, распознавание по тексту транскрипта — перила против рационализации, не защита от намеренного обмана.

**Claude Code, Cowork и Desktop; в Claude.ai — нет** (там механизма хуков нет, блок выпадает целиком). В Cowork хуки работают только при доставке плагином — `.claude/settings.json` установленной папки не читается. В режиме «Only on this computer» хук исполняется на машине пользователя с `cwd` в служебной папке сессии; корень пространства берётся из `CLAUDE_CODE_WORKSPACE_HOST_PATHS`. В облачном режиме хук исполняется в контейнере без доступа к папке и `SessionStart` не эмитится — карту там хуком не подать. Срез сред — [knowledge/plugins/!plugins.md](../../../knowledge/plugins/!plugins.md).

Хуки едут клиенту через сборщик: состав задаёт `manifest.txt` профиля, регистрацию на события — `settings.json` профиля. См. dev/plugin-builder/README.md.

## Что есть

| Файл | Событие | Что делает |
|------|---------|-----------|
| `inject_space_map.py` + `space_map.py` | UserPromptSubmit (первый промпт) · PostToolUse `mcp__.*__whoami` · PostToolUse `Read\|Glob\|Grep\|Bash` (подкарта ближайшего узла при первом обращении; пути Bash — из команды; маршруты README узла — после фильтра). Переменные `SVAIB_MAP_NESTED=0|chain` и `SVAIB_MAP_ROUTES=0` — формы для стенда замера, клиенту не нужны · SessionStart `compact\|clear` | **Карта пространства и стартовый контекст сессии** (трек space-map, 10.09): карта генерируется из дерева на первом промпте, зона пользователя — по ответу `whoami` платформы, подкарта узла — при первом обращении к нему (один раз за сессию), возврат карты после сжатия. `space_map.py` — генератор-библиотека, хук импортирует его модулем; в пространство ничего не пишется, агенту Bash не нужен. Регистрация четырёх событий — в `settings.json` (или `settings.merge.json`) профиля; готовый opt-in профиль — `dev/plugin-builder/profiles/svaib-space-map/`. Описание механики — [product/methodology/memory/navigation-workflow.md](../../methodology/memory/navigation-workflow.md) |
| `inject_file_spec.py` | PreToolUse `Write\|Edit\|MultiEdit\|Bash` (Codex — `apply_patch` и shell-инструменты) · SessionStart `compact\|clear` (Codex — PostCompact) | **Спецификация файла до записи** (A7b, решение продукта 11.09): первая в сессии запись в канонический файл — `NN_<тип kit>.md`, `meetings/*/summary.md`, справочные файлы по именам из спецификации `reference` — отклоняется, в причине отказа приходят `00_general.md` и спецификация типа (одним отказом; ориентир — 20 000 символов, проверенный вживую объём, больше — частями). Запись того же типа в первые 5 секунд после выдачи получает короткий отказ: это соседний вызов того же хода, модель ещё не видела спецификацию. Окно — эвристика по часам, не граница хода. Метки — по сессии и субагенту (у Codex `agent_id` в событии не гарантирован — тогда субагент делит метки с сессией), после сжатия снимаются. Запись оболочкой ловится базово: перенаправление, `tee`, `sed -i`, получатель `cp`/`mv`, скрипт `python`/`node` с явной записью; разбор оболочки общий с хуком карты (импорт). Не ловит запись через переменную и скрипт-файл, не засчитывает спецификацию, прочитанную агентом самим. Спецификации — `skills/space/scaffold/file-specs/` плагина, в репозитории svaib — [file-specs](../../methodology/scaffold/file-specs/README.md). Тесты — `dev/space-map/engine/tools/tests/test_file_spec.py`; вживую — Claude Code 2.1.276 и Codex 0.154.0 (18.09) |
| `check_deferred_actions.py` | Stop | Ловит «в следующий раз сделаю X». Следующей сессии не существует — хук требует предложить конкретную правку сейчас |

Хуки переносимы: не зависят от структуры репозитория. Хук карты ищет генератор рядом с собой (`space_map.py`), в репозитории svaib — в этой папке. Обязательный порядок пайплайна meeting-analysis держит сам скилл (`scripts/meeting_spine.py`) — Stop-хук-backstop `check_validation_contract.py` умер вместе с легаси-оркестраторами при переключении на spine (30.07).

## Долг

Внутренние хуки svaib живут отдельно, в `.claude/hooks/` репозитория. `check_deferred_actions.py` там и здесь сейчас идентичны — две копии, которые со временем разъедутся. Для хука карты канон — здесь, копия в `.claude/hooks/` репозитория — установка; тест трека (`dev/space-map/engine/tools/tests/test_n2.py`) держит их идентичными. Когда клиентских хуков станет больше трёх, свести к одному источнику.

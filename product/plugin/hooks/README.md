# Hooks — детерминированные правила у клиента

Хук — код, который платформа выполняет на событии сессии. В отличие от инструкции в `CLAUDE.md`, его нельзя «не заметить»: агент физически не может отменить запуск хука. Что именно хук способен доказать — вопрос его собственной логики: детерминированные проверки (перепрогон валидатора) — гарантия, распознавание по тексту транскрипта — перила против рационализации, не защита от намеренного обмана.

**Claude Code, Cowork и Desktop; в Claude.ai — нет** (там механизма хуков нет, блок выпадает целиком). В Cowork хуки работают только при доставке плагином — `.claude/settings.json` установленной папки не читается — и там не эмитится `SessionStart`, поэтому `inject_user_identity.py` в этом канале не срабатывает, пока не переедет на `UserPromptSubmit`. Срез сред — [knowledge/plugins/!plugins.md](../../../knowledge/plugins/!plugins.md).

Хуки едут клиенту через сборщик: состав задаёт `manifest.txt` профиля, регистрацию на события — `settings.json` профиля. См. ../profiles/README.md.

## Что есть

| Файл | Событие | Что делает |
|------|---------|-----------|
| `inject_space_map.py` + `space_map.py` | UserPromptSubmit (первый промпт) · PostToolUse `mcp__.*__whoami` · PostToolUse `Read\|Glob\|Grep\|Bash` (подкарта ближайшего юнита при первом обращении; пути Bash — из команды; маршруты README юнита — после фильтра). Переменные `SVAIB_MAP_NESTED=0|chain` и `SVAIB_MAP_ROUTES=0` — формы для стенда замера, клиенту не нужны · SessionStart `compact\|clear` | **Карта пространства и стартовый контекст сессии** (трек space-map, 10.09): карта генерируется из дерева на первом промпте, зона пользователя — по ответу `whoami` платформы, подкарта юнита — при первом обращении к нему (один раз за сессию), возврат карты после сжатия. `space_map.py` — генератор-библиотека, хук импортирует его модулем; в пространство ничего не пишется, агенту Bash не нужен. Регистрация четырёх событий — в `settings.json` (или `settings.merge.json`) профиля; готовый opt-in профиль — `dev/plugin-builder/profiles/svaib-space-map/`. Описание механики — [product/methodology/memory/navigation-workflow.md](../../methodology/memory/navigation-workflow.md) |
| `inject_user_identity.py` | SessionStart | Сообщает агенту, кто за клавиатурой — читает `.agents/identity.local`. Имя владельца по умолчанию подставляется из `vars.conf` профиля (`{{DEFAULT_USER}}`), переопределяется переменной `SVAIB_DEFAULT_USER`. ❗️ У клиентов с MCP svaib источник «кто» — `whoami` через хук карты; этот хук остаётся для пространств без MCP (решение о снятии — при включении карты в клиентский профиль) |
| `check_deferred_actions.py` | Stop | Ловит «в следующий раз сделаю X». Следующей сессии не существует — хук требует предложить конкретную правку сейчас |

Хуки переносимы: не зависят от структуры репозитория. Хук карты ищет генератор рядом с собой (`space_map.py`), в репозитории svaib — в этой папке. Обязательный порядок пайплайна meeting-analysis держит сам скилл (`scripts/meeting_spine.py`) — Stop-хук-backstop `check_validation_contract.py` умер вместе с легаси-оркестраторами при переключении на spine (30.07).

## Долг

Внутренние хуки svaib живут отдельно, в `.claude/hooks/` репозитория. `check_deferred_actions.py` там и здесь сейчас идентичны — две копии, которые со временем разъедутся. Для хука карты канон — здесь, копия в `.claude/hooks/` репозитория — установка; тест трека (`dev/space-map/engine/tools/tests/test_n2.py`) держит их идентичными. Когда клиентских хуков станет больше трёх, свести к одному источнику.

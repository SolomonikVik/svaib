# Hooks — детерминированные правила у клиента

Хук — код, который платформа выполняет на событии сессии. В отличие от инструкции в `CLAUDE.md`, его нельзя «не заметить»: агент физически не может отменить запуск хука. Что именно хук способен доказать — вопрос его собственной логики: детерминированные проверки (перепрогон валидатора) — гарантия, распознавание по тексту транскрипта — перила против рационализации, не защита от намеренного обмана.

**Только Claude Code.** В Claude.ai и Cowork механизма хуков нет — при поставке на такой runtime блок хуков выпадает целиком.

Хуки едут клиенту через сборщик: состав задаёт `manifest.txt` профиля, регистрацию на события — `settings.json` профиля. См. ../profiles/README.md.

## Что есть

| Файл | Событие | Что делает |
|------|---------|-----------|
| `inject_user_identity.py` | SessionStart | Сообщает агенту, кто за клавиатурой — читает `.agents/identity.local`. Имя владельца по умолчанию подставляется из `vars.conf` профиля (`{{DEFAULT_USER}}`), переопределяется переменной `SVAIB_DEFAULT_USER` |
| `check_deferred_actions.py` | Stop | Ловит «в следующий раз сделаю X». Следующей сессии не существует — хук требует предложить конкретную правку сейчас |

Оба хука переносимы: не зависят от структуры репозитория. Обязательный порядок пайплайна meeting-analysis держит сам скилл (`scripts/meeting_spine.py`) — Stop-хук-backstop `check_validation_contract.py` умер вместе с легаси-оркестраторами при переключении на spine (30.07).

## Долг

Внутренние хуки svaib живут отдельно, в `.claude/hooks/` репозитория. `check_deferred_actions.py` там и здесь сейчас идентичны — две копии, которые со временем разъедутся. Когда клиентских хуков станет больше трёх, свести к одному источнику.

## Планы

| Триггер | Действие |
|---------|---------|
| После обработки встречи | Обновление файлов проекта по итогам |
| При закрытии сессии | Разбор содержания сессии → распределение по файлам |

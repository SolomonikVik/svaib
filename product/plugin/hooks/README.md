# Hooks — детерминированные правила у клиента

Хук — код, который платформа выполняет на событии сессии. В отличие от инструкции в `CLAUDE.md`, его нельзя «не заметить»: агент физически не может отменить запуск хука. Что именно хук способен доказать — вопрос его собственной логики: детерминированные проверки (перепрогон валидатора) — гарантия, распознавание по тексту транскрипта — перила против рационализации, не защита от намеренного обмана.

**Claude Code, Cowork и Desktop; в Claude.ai — нет** (там механизма хуков нет, блок выпадает целиком). В Cowork хуки работают только при доставке плагином — `.claude/settings.json` установленной папки не читается. В режиме «Only on this computer» хук исполняется на машине пользователя с `cwd` в служебной папке сессии; корень пространства берётся из `CLAUDE_CODE_WORKSPACE_HOST_PATHS`. В облачном режиме хук исполняется в контейнере без доступа к папке и `SessionStart` не эмитится — карту там хуком не подать. Срез сред — [knowledge/plugins/!plugins.md](../../../knowledge/plugins/!plugins.md).

Хуки едут клиенту через сборщик: состав файлов задаёт `manifest.txt` профиля, регистрацию на события в плагине — `hooks.json` профиля. См. dev/plugin-builder/README.md. Архитектура роста хуков и план телеметрии — dev/plugin-hooks/.

В Codex Desktop свёрнутые строки настроек называются «Хук 1», «Хук 2» даже при заполненном `statusMessage`. Перед выдачей доверия раскройте строку стрелкой: в деталях видны текст выполнения и команда ([ограничение Codex](https://github.com/openai/codex/issues/41611)).

## Что есть

| Файл | Событие | Что делает |
|------|---------|-----------|
| `inject_space_map.py` + `space_map.py` + `hook_space.py` | UserPromptSubmit (первый промпт) · PostToolUse `mcp__.*__whoami` · PostToolUse `mcp__.*__update_me` (статус онбординга и настройки в кэш, без вывода) · PostToolUse `Read\|Glob\|Grep\|Bash` (подкарта ближайшего узла при первом обращении; пути Bash — из команды; маршруты README узла — после фильтра). Переменные `SVAIB_MAP_NESTED=0|chain` и `SVAIB_MAP_ROUTES=0` — формы для стенда замера, клиенту не нужны · SessionStart `compact\|clear` | **Карта пространства и стартовый контекст сессии** (трек space-map, 10.09): карта генерируется из дерева на первом промпте, зона пользователя — по ответу `whoami` платформы, подкарта узла — при первом обращении к нему (один раз за сессию), возврат карты после сжатия. Под строкой «За клавиатурой» — ближайшие этапы онбординга, «два и два» (контракт): статус `onboarding` из кэша `whoami` (версия кэша 3) × каталог `skills/space-onboarding/references/stages.json` рядом с хуком — его собирает сборка из таблиц `product/methodology/onboarding.md`, без поставки каталога блока нет; ответ `update_me` обновляет в кэше пришедшие статус и `preferences` (пустые — очищают), отказ `onboarding-conflict` — только статус; срок записи не продлевается; нет статуса, каталога или любой сбой — блока нет, карта приходит. Тесты — `dev/space-map/engine/tools/tests/test_onboarding_hook.py`. `space_map.py` — генератор-библиотека, хук импортирует его модулем; в пространство ничего не пишется, агенту Bash не нужен. Регистрация пяти событий — в `settings.json` (или `settings.merge.json`) профиля; запаркованный профиль — `dev/plugin-builder/_parked/profiles/svaib-space-map/`. Описание механики — [product/methodology/memory/navigation-workflow.md](../../methodology/memory/navigation-workflow.md) |
| `inject_file_spec.py` | PreToolUse `Write\|Edit\|MultiEdit\|Bash` (Codex — `apply_patch` и shell-инструменты) · SessionStart `compact\|clear` (Codex — PostCompact) | **Спецификация файла до записи** (A7b, решение продукта 11.09): первая в сессии запись в канонический файл — `NN_<тип kit>.md`, `meetings/*/summary.md`, справочные файлы по именам из спецификации `reference` — отклоняется, в причине отказа приходят `00_general.md` и спецификация типа (одним отказом; ориентир — 20 000 символов, проверенный вживую объём, больше — частями). Запись того же типа в первые 5 секунд после выдачи получает короткий отказ: это соседний вызов того же хода, модель ещё не видела спецификацию. Окно — эвристика по часам, не граница хода. Метки — по сессии и субагенту (у Codex `agent_id` в событии не гарантирован — тогда субагент делит метки с сессией), после сжатия снимаются. Запись оболочкой ловится базово: перенаправление, `tee`, `sed -i`, получатель `cp`/`mv`, скрипт `python`/`node` с явной записью. Inline Python разбирается без исполнения: присваивания по порядку, конкатенация строк, списки/кортежи путей и накопление словаря с записью через `.items()`; проверка ссылок сама записью не считается. Все найденные цели группируются по типу, каждому типу подаётся его спецификация; остаток по бюджету приходит при повторе. Разбор обёрток оболочки общий с хуком карты (импорт). Не ловит запись через переменную оболочки, динамически вычисляемый путь и скрипт-файл, не засчитывает спецификацию, прочитанную агентом самим. Спецификации — `skills/space-scaffold/file-specs/` собранного пакета, в репозитории svaib — [file-specs](../../methodology/space/scaffold/file-specs/README.md). Тесты — `dev/space-map/engine/tools/tests/test_file_spec.py`; вживую — Claude Code 2.1.276 и Codex 0.154.0 (18.09) |
| `usage_log.py` + `usage_claude.py` + `usage_codex.py` | PreToolUse `Skill`/`Agent`/`Task` · UserPromptSubmit · Stop · SessionEnd | **Учёт использования скиллов**: строки запуска в `.svaib/usage/<хост>.md` — ход основной сессии или субагент, общие `сессия` и `запуск`; контракт — `.svaib/usage/README.md`. Запуск — от вызова до команды другого скилла, чужой команды, суток паузы или конца сессии; вызов моделью внутри запуска — вложенный отрезок. Claude Code — `Skill`, `/svaib:<скилл>`, `Agent` с путём к `SKILL.md` пакета; субагенты — из `subagents/agent-<id>.jsonl`, адаптер `usage_claude.py`. Codex — `$<скилл>` и неявный вызов по правилу самого Codex (команда прочитала `SKILL.md` или скрипт скилла), субагенты — их rollout по `root_turn_id`, адаптер `usage_codex.py`; Stop читает rollout с начала хода и только при признаках скилла или субагента. Несколько явных скиллов Codex в одном ходе получают строки с пустым общим расходом; идентичность Codex не покрыта. Строки пишутся следующим запросом или концом сессии. Файл со старой шапкой отодвигается рядом, учёт не замолкает. Вне готового пространства (`hook_space.ready_usage_root`) выходит до чтения транскрипта и записей; состояние — вне базы. Тесты и живые стенды — `dev/plugin-hooks/tests/`, приёмка Codex. |
| `check_deferred_actions.py` | Stop | Ловит «в следующий раз сделаю X». Следующей сессии не существует — хук требует предложить конкретную правку сейчас |

Хуки переносимы: не зависят от структуры репозитория. Хук карты ищет генератор рядом с собой (`space_map.py`), в репозитории svaib — в этой папке. Корень сессии выбирает `hook_space.py` рядом с хуком — один для карты и спецификации; учёт использования берёт тот же корень и пишет, только если действие не ушло в другую базу. Без `hook_space.py` хуки выходят с кодом 0, ошибка — в stderr и лог. Обязательный порядок пайплайна meeting-analysis держит сам скилл (`scripts/meeting_spine.py`) — Stop-хук-backstop `check_validation_contract.py` умер вместе с легаси-оркестраторами при переключении на spine (30.07).

## Долг

Внутренние хуки svaib живут отдельно, в `.claude/hooks/` репозитория. Две версии `check_deferred_actions.py` уже различаются языком текста отказа: у клиента русский, внутри английский. Перед объединением исходника нужно решить, сохранять ли это различие. Для хука карты канон — здесь, копия в `.claude/hooks/` репозитория — установка; тест трека (`dev/space-map/engine/tools/tests/test_n2.py`) держит их идентичными. Общая архитектура и границы кода — в треке хуков.

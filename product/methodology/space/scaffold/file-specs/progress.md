# Спецификация типа `progress` — хроника

Общие правила — [00_general.md](00_general.md). Здесь только специфика типа.

## Миссия

Файл вида `04_progress.md`. Фиксирует, **что произошло с узлом во времени**: значимые события, изменения, итоги периодов, завершённые шаги. Помогает видеть движение узла, а не только его текущее состояние ([management-kit:91–104](../management-kit.md#L91)).

**Граница:** не журнал решений — мотив выбора живёт в [decisions](decisions.md); не `active` — текущее состояние там.

Отвечает на вопрос «как двигались». Читается, когда нужно восстановить траекторию.

## Структура секций

Плоский список датированных блоков, **свежее сверху**. По [templates/management-kit/04_progress.md](../../../../plugin/skills/space/scaffold/templates/management-kit/04_progress.md) шаблон даёт две формы блока:

- событие: `## YYYY-MM-DD — {событие / сдвиг}` + **Что произошло** + **Почему важно**;
- встреча: `## YYYY-MM-DD — встреча: {тема}` + **Участники** + **Ключевое** (2–4 строки) + **Источник:** ссылка на протокол в `meetings/`.

Дата — дата события или встречи, а не дня обработки: разбор недельной давности не переносит запись в сегодня. **Место новой записи — по объявленному правилу файла** («сверху» или по дате): правило файла решает, куда она встаёт, а дата в самой записи всегда остаётся датой события; при разборе задним числом порядок уже лежащих записей не перестраивается. Заголовки уникальны целиком: две встречи одного дня дают два блока одной даты с разными заголовками.

**Поле «Источник»** держим обязательным для блока встречи: без него теряется связь выжимка ↔ хроника.

## Что входит

Событие, изменившее состояние объекта: пройденный этап, полученный результат, сдвиг в способе работы, итог периода. Не перечень обсуждённого, а результат.

## Что не входит

Задачи и планы. Правка старых записей. Пересказ хода встречи. Служебные отметки о самом факте разбора. Решения с их мотивом — они в [decisions](decisions.md).

## Как событие встречи меняет файл

| Событие на встрече | Что делает файл |
|---|---|
| встреча что-то сдвинула | появляется блок своей даты: участники, ключевое, ссылка на протокол |
| встреча ничего не сдвинула | записи нет — это штатный исход |
| задача из `active` закрыта, и закрытие значимо для движения | результат называется внутри «Ключевого» записи о встрече; отдельной записи не заводится |
| задача снята, отменена или перерешена | записи нет — хроника фиксирует продвижение, а не снятие |
| принято решение | сюда идёт только факт сдвига; мотив и альтернативы — в [decisions](decisions.md) |
| прежняя запись оказалась неточной | старая запись не правится; уточнение идёт записью своей даты |
| блок этой даты и этой встречи уже есть | повторный разбор переписывает запись этой встречи целиком; второй блок не заводится |

## Гранулярность записи

Одна встреча — одна запись, с обязательным полем «Источник». Закрытые задачи называются внутри «Ключевого» (2–4 строки) только если закрытие значимо для движения объекта — по самопроверке ниже; отдельной записи на задачу не заводится. Снятая или отменённая задача в хронику не идёт вовсе: её парная половина — только удаление из [active](active.md).

Так исполняется и вторая половина парной правки `done` из [00_general](00_general.md#форма-записи) — строкой внутри записи о встрече, а не отдельной записью.

## Закрытие и обновление записей

Запись пишется один раз и после этого не правится: хроника — история, а не состояние. Устаревшее не переписывается, а уточняется новой записью своей даты.

**Единственное исключение — повторный разбор той же встречи:** запись **этой** встречи переписывается целиком — одна встреча, одна запись. Записи других встреч при этом не трогаются, и дописывания «ещё абзац в старый блок» не бывает.

## Здоровый размер и признаки раздутости

Ориентир <300 строк; переросшую хронику дробят по периодам с явными связями — это решение человека, не разбора. Здоровая хроника читается подряд и показывает движение; она не дублирует протокол встречи и не заменяет `active`.

Признаки раздутости: запись есть после каждой встречи независимо от сдвига · «Ключевое» пересказывает ход обсуждения вместо результата · в блоках появились задачи и планы · старые записи правились · нет ссылки на протокол, и через полгода источник не найти.

## Самопроверка

Один вопрос по каждой записи: **через полгода эта фраза объяснит что-нибудь о движении объекта?**

- «Договорились о структуре повестки: сначала метрики, потом проекты» — объяснит.
- «Обсудили повестку, клиент дал обратную связь» — не объяснит, это операционная подробность.

Не прошло — не пишется. Отсутствие записи о встрече допустимо.

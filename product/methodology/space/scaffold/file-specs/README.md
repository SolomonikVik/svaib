# file-specs — спецификации канонических файлов

Перечень канонических файлов пространства и их спецификаций. Канонический файл — файл из этого перечня: у него есть имя, миссия и спецификация.

Перед записью в канонический файл агент читает [общий файл](00_general.md), затем спецификацию этого файла. Какую брать, видно по имени файла, а где имя меняется под предмет — по месту.

## Содержимое папки

- [00_general.md](00_general.md) — общий файл: что верно для любого канонического файла.
- [overview.md](overview.md) — `01_overview.md`, обзор узла.
- [active.md](active.md) — `02_active.md`, текущая работа.
- [backlog.md](backlog.md) — `03_backlog.md`, будущая работа.
- [progress.md](progress.md) — `04_progress.md`, хроника.
- [decisions.md](decisions.md) — `05_decisions.md`, журнал решений.
- [meeting-summary.md](meeting-summary.md) — `summary.md` в папке встречи, выжимка встречи: где она лежит; форму задаёт спецификация разбора встречи.
- [reference.md](reference.md) — `person.md`, `profile.md`, `architecture.md`, `setup.md`, `glossary.md`, `speech-aliases.md`, с необязательным `NN_`: общие правила шести видов справочных файлов; структура каждого — из его шаблона.

## Подключить спецификацию к хуку

Положи спецификацию отдельным `.md`-файлом в эту папку. В YAML-шапке укажи `title`, `status` и `file_patterns` — непустой JSON-массив масок на одной строке:

```yaml
---
title: "Тип example — миссия файла"
status: draft
file_patterns: ["[0-9][0-9]_example.md", "meetings/*/example.md"]
---
```

- Маска одного имени действует в любом узле. Маска с `/` совпадает с концом пути от корня пространства: `meetings/*/example.md` подходит и для `sales/meetings/2026-10-10_sync/example.md`.
- `*`, `?` и `[]` работают внутри одной части пути; `*` не перескакивает через папки. Регистр не учитывается. Абсолютные пути, `.`/`..`, обратные слеши и `**` запрещены.
- Необязательный числовой префикс задаётся двумя масками: `"profile.md"` и `"[0-9][0-9]_profile.md"`. `?` означает ровно один символ, а не необязательную часть.
- Если подходят несколько спецификаций, хук выдаёт все. Общий файл `00_general.md` приходит первым; `README.md` этой папки не является спецификацией типа.
- Новые файлы и изменения масок видны при следующем запуске хука, в том числе в текущей сессии. Текст каждой спецификации подаётся один раз за сессию, после сжатия — снова.
- Файлы вне пространства, скрытые папки, `_templates/`, `zz_archive/`, `node_modules/` и `scaffold/templates/` исключены независимо от масок. Сами спецификации хук тоже не перехватывает.

Хук читает только эту папку и не выводит маски из текста или имени спецификации. Её каталог поставляется целиком; Python-код и манифест для нового типа менять не нужно. Спецификация без корректного `file_patterns` останавливает сборку пакета. При повреждении уже установленной спецификации хук пишет причину в лог и продолжает работать с остальными.

Это охват по именам и путям: профиль с произвольным именем человека не распознаётся только по содержимому. Дополнительные каноны вне этой папки автоматически не подключаются.

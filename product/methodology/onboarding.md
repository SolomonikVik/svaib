# Онбординг — последовательность освоения Second Value AI Brain

## Кратко
❗️ файл требует тщательной переработки по содержанию — на последовательность этапов и фазы программы не опираться. Пути и раскладка приведены к scaffold v4.1 (04.08), канон структуры — [scaffold/deployment.md](scaffold/deployment.md).

Последовательность, в которой клиент осваивает систему Second Value AI Brain: от первого артефакта до работающей системы. Каждый этап заканчивается работающим артефактом — клиент получает ценность сразу, не "когда всё будет готово".

## Связанные файлы

- methodology.md — ритуалы и протоколы (начинают работать после онбординга)
- ontology/ontology.md — какие сущности заполняются на каждом этапе
- ../plugin/skills/scaffold/template/ — каркас, который клиент разворачивает и заполняет
- ../../clients/playbook/delivery/01_delivery_plan.md — тактика онбординга (ДЗ, шаблоны сообщений, инструменты)

## Scope системы

Second Value AI Brain — AI-инфраструктура для управления бизнесом. Система знает руководителя как личность (ценности, стиль, компетенции), чтобы помогать в бизнесе. Личные домены вне бизнеса (здоровье, хобби, семья) — вне scope. Scaffold разворачивается только для бизнес-проектов. В `00_ceo/01_profile.md` могут упоминаться значимые не-бизнес-проекты, если они влияют на бизнес-решения (обучение, переезд) — но как контекст, не как отдельная инфраструктура.

При онбординге объяснить клиенту эту границу — чтобы в рабочем пространстве не появлялись медкарты и хобби-проекты.

Детали решения — [05_decisions.md](../05_decisions.md) (пункт 2 — Границы продукта).

## Принципы

1. **Каждый этап = работающий артефакт.** Не "подготовка к будущему", а ценность прямо сейчас. `00_ceo/01_profile.md` уже персонализирует AI. Vision уже даёт фокус.
2. **От личного к бизнесу.** Сначала человек (`00_ceo/01_profile.md`), потом курс компании (`01_company/01_strategic/`), потом операционка (`02_team/`, узлы направлений, `processes/`). "Личное" здесь = ценности и стиль мышления в контексте бизнеса, не вся жизнь.
3. **Минимальный жизнеспособный набор.** Система "запускается" после этапа 2 (`00_ceo/01_profile.md` + `01_company/01_strategic/vision.md` + `01_company/01_strategic/goal.md` + `01_company/02_active.md`). Остальное — расширение.
4. **Верификация артефактов.** Заполненный файл нужно проверить — работает ли он для AI как контекст (см. секцию "Верификация").

## Последовательность

### Этап 0. Pre-work

**Что:** Клиент до первой встречи собирает исходные данные.

- Список проектов/направлений (2-3 ключевых)
- Существующие документы (стратегия, планы, если есть)
- Формулировка болей ("что не работает", "чего не хватает")

**Артефакт:** Входные данные для первой встречи.

### Этап 1. Персональный профиль CEO

**Что:** Заполнение `00_ceo/01_profile.md` — кто клиент, ценности, стиль мышления, фокус.

**Как:** Через AI-интервью (AI задаёт вопросы по scaffold-шаблону) или самостоятельно.

**Верификация:** Инкогнито-тест (см. секцию ниже).

**Артефакт:** Заполненный `00_ceo/01_profile.md`. AI уже может персонализировать рекомендации.

### Этап 2. Vision + Goals + Plan — управленческое ядро

**Что:** Заполнение `01_company/01_strategic/vision.md` → `01_company/01_strategic/goal.md` → `01_company/02_active.md`.

**Как:** Последовательно, каждый следующий файл опирается на предыдущий. Vision → "куда идём". Goal → "что хотим достичь в этом периоде". Plan → "что делаем на этой неделе".

**Артефакт:** Работающий управленческий контур. AI знает: кто клиент, куда идёт, что делает сейчас. Можно начинать еженедельный ритуал.

**Система запущена.** После этого этапа клиент может работать в еженедельном ритме (methodology.md → "Еженедельный ритуал").

### Этап 3. Настройка AI-интерфейса

**Что:** Конфигурация AI-инструмента клиента (Claude Projects, Cowork, VS Code) — User Preferences, Project Instructions, подключение файлов.

**Как:** На основе заполненных `00_ceo/01_profile.md` + `01_company/01_strategic/vision.md` + `01_company/01_strategic/goal.md`. Можно генерировать через промпт.

**Артефакт:** Настроенный AI-интерфейс, который знает контекст клиента.

### Этап 4+. Расширение — по мере необходимости

**Что:** Постепенное заполнение сущностей по мере работы. Файлы уже существуют с первого дня — вопрос в том, когда наполнять:

| Сущность | Когда заполнять |
|----------|----------------|
| 01_company/05_decisions.md | При первом стратегическом решении компании |
| 00_ceo/03_thoughts.md | При накоплении идей, гипотез, рефлексий |
| 00_ceo/04_decisions.md | При первом личном решении CEO |
| `02_team/{имя}.md` у владельца | При первом появлении человека с явной ролью |
| `{unit}/` — узел направления | При первой встрече, задаче или регулярном фокусе по направлению |
| `product/`, `processes/`, `clients/`, `knowledge/` | По живой работе в домене (опциональные) |

**Принцип v4.1:** с первого дня существует стартовый каркас `01_company/` (курс, команда, метрики) плюс `00_ceo/`, если руководитель ведёт личный контур. Всё остальное — узлы направлений, ракурсы, файлы панели — разворачивается только под живую работу. Пустых веток не создаём: канон — [scaffold/deployment.md](scaffold/deployment.md).

## Верификация артефактов

### Инкогнито-тест

**Суть:** Заполненный файл бросается в "чистый" AI-чат (без контекста сессии, без истории) с промптом-верификатором. AI оценивает файл как независимый читатель.

**Зачем:** Тестирует сам артефакт, а не способность клиента объяснить себя в диалоге. Если AI в чистом чате понимает клиента — файл работает.

**Промпт-верификатор (для MyProfile):**

> Ты — AI-ассистент, который будет работать с этим человеком как партнёр: помогать думать, планировать, принимать решения, готовить документы. Этот профиль — твой ключевой источник контекста о нём. Ты обращаешься к нему, чтобы персонализировать рекомендации, фильтровать решения через его ценности и понимать, в каком контексте он работает.
>
> Прочитай профиль и ответь:
> 1. Что тебе стало понятно про этого человека? Кратко, своими словами.
> 2. Достаточно ли тебе этого, чтобы начать эффективно работать с ним?
> 3. Где есть противоречия или несостыковки?
> 4. Какие вопросы остались — что бы ты хотел уточнить?
> 5. Есть ли что-то лишнее, что не помогает тебе как AI-партнёру?

**Статус:** Проверено на `00_ceo/01_profile.md` (март 2026). Применимость к другим сущностям (`01_company/01_strategic/vision.md`, `01_company/01_strategic/goal.md`) — открытый вопрос.

## Фазы программы (стратегический горизонт)

Этапы выше — минимальная последовательность. В рамках полной программы работы с клиентом выделяются фазы:

| Фаза | Фокус | Результат |
|------|-------|-----------|
| 0. Pre-work | Сбор данных | `00_ceo/01_profile.md` |
| 1. Personal OS | Личная система | Настроенный AI, `00_ceo/01_profile.md`, `01_company/01_strategic/` и первые ритуалы |
| 2. Business context | Контекст компании | Scaffold компании, ключевые процессы |
| 3. Processes + автоматизация | Оживление системы | Автоматизированный процесс, метрики |
| 4. Масштабирование | Развитие | 90-дневный план развития |

Принцип прогрессии: **личное → команда → компания → измерение**. Каждая фаза производит артефакт, который "работает на следующий день".

Детали по фазам уточняются через реальные кейсы.

# metrics-intake — спецификация результата

Черновая спецификация по [авторскому исходнику](business-metrics-intake.md), пересобранная по решению Эрика. Ещё не принята ответственным за продуктовый слой.

## Цель и управленческая ценность

Руководитель вместе с партнёром формулирует компактный набор ключевых бизнес-метрик своей компании. Набор отражает её экономику и стратегию, показывает движение к целям и помогает понять, на что руководитель может влиять.

## Контекст

- Vision компании — миссия, идентичность, для кого работает бизнес.
- Goal компании — долгосрочная цель, стратегия, OKR года.
- Существующий набор метрик, если он есть, и разговор с руководителем.
- Шаблон `business-metrics.md` из `space-scaffold` — форма записи результата и правила заполнения.

Адреса контекста и рабочего файла берутся из карты и README пространства. Если vision/goal отсутствует или размыт, сначала нужно прояснить с руководителем, к чему бизнес движется и что в этом можно измерять. Intake не придумывает цели вместо руководителя и не меняет файлы целей.

## Набор и смысл метрик

- Каждая метрика показывает движение к чему-то из vision/goal; связь понятна руководителю.
- Новая метрика нужна, только если её нельзя выразить через существующие и без неё теряется важное. Число метрик определяется бизнесом, показатели ради полноты не добавляются.
- Есть запаздывающие показатели результата и опережающие показатели, на которые руководитель влияет сегодня, чтобы двигать результат завтра. Ориентир — примерно 2:1 в пользу опережающих; это не требование добрать количество.
- Исследована экономика бизнеса. У большинства бизнесов есть profit per X, где X — то, что компания масштабирует: точки, клиенты, рейсы, подписки. Если такая метрика осмысленна для этой компании, она найдена; искусственный знаменатель не подбирается.
- Не упущены главная метрика дохода, главная метрика клиентского движения (приход/уход) и главная метрика здоровья бизнеса.
- У каждой метрики есть управленческое действие. Если руководитель может только смотреть на показатель и не может на него влиять, такой показатель не включается как ключевая метрика.
- Каждая метрика осмыслена руководителем. Имя — как её называют в компании; варианты предлагает партнёр, решает руководитель. Бизнес-смысл, правило расчёта на языке бизнеса с явной временной логикой, единица и направление изменения определены по шаблону.

## Результат в разговоре

Руководитель видит сводку всего предложенного набора, связь с vision/goal и управленческими действиями, опережающие и запаздывающие показатели, спорные места и точную предлагаемую правку файла. Партнёр спрашивает, отражает ли набор движение бизнеса и чего не хватает. При сомнениях обсуждение продолжается.

При пересмотре существующего набора видна судьба прежних метрик. Набор и запись согласуются до изменения файла; несогласованное и не затронутое сохраняется. Удаление метрики требует явного согласия на точную правку.

## Запись и границы

Согласованный набор записывается разом в базовый файл бизнес-метрик по шаблону и правилам пространства. Если запись не разрешена, подготовленный результат остаётся в разговоре. При паузе сохраняются промежуточное состояние мысли и открытые вопросы; завершать всё за одну сессию не требуется.

Intake формулирует метрики и их смысл. Живые значения и расчёты по книгам — задача `metrics-values`. Настройка источников и правка книг в intake не входят. Известные привязки к источникам сохраняются, неизвестные не выдумываются.

Если источники всего нового набора пока неизвестны, шаблон может быть заполнен частично с явным обозначением незаполненного. Если в существующем файле уже есть известные привязки к источникам, новую метрику без достоверной привязки оставляют в разговоре: она не должна получить общий или чужой источник только из-за записи в этот файл. Остальные согласованные изменения могут быть записаны отдельно; такая метрика остаётся предложением, не частью записанного набора.

## Признак готовности

Руководитель согласовал набор и смысл каждой метрики, поля паспортов определены по шаблону, спорное разрешено либо явно оставлено вне согласованного набора. При разрешённой записи согласованная правка выполнена и проверена; без разрешения готовый результат остаётся в разговоре.

Согласованный набор без источников завершает формулирование, но ещё не даёт готового входа для `metrics-values`. Подготовку нового паспорта в разговоре и его запись в файл различают; ограничение записи при неизвестной привязке не выдаётся за выполненную запись.

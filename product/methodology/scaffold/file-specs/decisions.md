# Спецификация типа `decisions` — журнал решений

Общие правила — [00_general.md](00_general.md). Здесь только специфика типа.

## Миссия **[канон]**

Файл вида `05_decisions.md`. Реестр решений по узлу: что выбрали, почему, какие альтернативы рассматривали, что это меняет ([management-kit:106–120](../management-kit.md#L106)).

**Граница:** не хроника событий — события в [progress](progress.md).

**[стенд]** Отвечает на вопрос «почему сделано так, а не иначе». Через три месяца это единственное место, где сохранился мотив выбора.

## Структура секций **[канон, шаблон]**

Плоский список записей, **свежее сверху**. По [_templates/management-kit/05_decisions.md](../../../plugin/skills/scaffold/template/_templates/management-kit/05_decisions.md):

`## YYYY-MM-DD: {Название решения}` → **Решение** (что именно решили) · **Почему** (кратко) · **Альтернативы** (если важны).

Решение без «почему» — половина записи: в отрыве от мотива оно бессмысленно **[стенд]**.

## Что входит **[стенд]**

> ❗️ **ГЭП в условиях допуска.** Третий пункт ниже соединяет определение решения с одной конкретной схемой его принятия и подтверждения. Из-за этого схема разговора становится частью типа сущности.
>
> **Предлагаемая правка:** определение решения опереть на [entities.md](../../ontology/entities.md#атомарные-11) — выбор, закрывающий альтернативы. Достаточность оснований, полномочия принимающего и состав затронутых сторон проверять отдельным контуром для конкретного решения. Опора — [гипотеза §2.4](../../rhythm/meeting-analysis/workflow.md#24-состав-темы).

Запись появляется, когда выполнены три условия сразу:

1. выбор сделан между различимыми вариантами;
2. выбор меняет способ работы, а не только ближайший шаг;
3. решение приняла сторона, имеющая право его принять, и вторая сторона его услышала.

## Что не входит **[стенд]**

Задачи. Планы. Намерения. Идеи. Договорённости «кто что пришлёт». Обсуждение без выбора — это открытый вопрос для [active](active.md). Предложение одной стороны без ответа второй.

## Как событие встречи меняет файл **[стенд + канон]**

| Событие на встрече | Что делает файл |
|---|---|
| принято новое решение | добавляется запись сверху, со ссылкой на то, что она замещает |
| прежнее решение перерешено | старая запись помечается `Superseded` со ссылкой на новую; её текст не правится |
| решение исполнено | запись не трогается вовсе; исполнение — событие для [progress](progress.md) |
| обсуждали, но не выбрали | записи нет — это открытый вопрос для [active](active.md) |
| одна сторона предложила, вторая не ответила | записи нет |

## Исполненное решение **канон, развилка снята [Э12]**

Принятая запись не переписывается вовсе и **поля статуса не получает** — ни «Реализовано», ни «Исполнено»: она либо действует, либо помечена `Superseded` со ссылкой на новую. Исполнение решения — событие, и его место в [progress](progress.md); в журнале решений замены не бывает ([management-kit:118](../management-kit.md#L118), formats.md:46).

Отметки исполнения, уже стоящие в живом журнале, прецедентом не являются: разбор называет их в findings как работу хранителя и не копирует — шапка того же файла обычно объявляет «принятые решения не переписывать», а объявление сильнее формы соседей ([00_general — приоритет правил формы](00_general.md#форма-записи)).

## Закрытие и обновление записей **[канон]**

Единственная допустимая правка прежней записи — пометка `Superseded` со ссылкой на новую; её ставит тот, кто вносит замещающее решение. Пересмотр решения — всегда новая запись, а не редактирование старой: журнал живёт как история выбора, а не как текущее состояние дел.

## Здоровый размер и признаки раздутости

**[канон]** Ориентир <300 строк; переросший журнал разворачивается в папку `decisions/` — решение человека, не разбора. **[стенд]** Файл растёт медленно: за встречу здесь появляется ноль, одна, редко две записи.

Признаки раздутости **[draft]**: в журнале лежат задачи и намерения · запись без «почему» · две записи об одном выборе вместо `Superseded`-цепочки · старые записи правились · после каждой встречи есть запись — верный признак, что за решение выдают обсуждение.

## Самопроверка **[стенд]**

Сформулируй запись и прочитай её глазами человека, который придёт в проект через три месяца. Он спросит «кто это решил и почему» — файл отвечает? Нет — запись не готова.

Отдельно проверь: не выдаёшь ли за решение то, что прозвучало предложением и осталось без ответа ([00_general — статус сказанного сохраняется](00_general.md#статус-сказанного-сохраняется-стенд--гипотеза-27)).

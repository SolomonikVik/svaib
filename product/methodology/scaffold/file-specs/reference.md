# Спецификация справочных файлов

Общие правила — [00_general.md](00_general.md). Здесь только специфика типа.

Спека стенда для этого типа — самая сильная из шести: канон правил записи в справочные файлы не даёт вовсе (E §4). Поэтому поведение — **[стенд]** целиком, миссии файлов — **[канон]**.

## Миссия

Файлы, описывающие **устойчивое положение дел, а не работу**: профиль человека, паспорт сущности, описание бизнеса, устройство системы, конфигурация и статус поставки, словари. Отвечают на вопрос: **как устроено то, с чем мы работаем** **[стенд]**.

Типовые смысловые файлы канона ([01_architecture:202](../01_architecture.md#L202), [_templates/semantic-files/](../../../plugin/skills/scaffold/template/_templates)):

| Файл | Миссия |
|---|---|
| `person.md` / `profile.md` | профиль человека или паспорт сущности: кто/что это по сути, роль, зона, стиль |
| `architecture.md` | как устроен продукт, система, процесс или сложный объект |
| `setup.md` | рабочая конфигурация: инструменты, доступы, пространства, папки, правила подключения |
| `glossary.md` | канонический словарь терминов: принятые названия, определения, маппинг разговорных на канон |
| `speech-aliases.md` | словарь распознавания речи: варианты имён, ASR-ошибки, жаргон, сокращения |

Формы, уникальные для типа узла (`00_ceo/01_profile.md`, `product/profile.md`, `01_company/operating-model.md`), сюда не входят — их описывает [management-unit](../management-unit.md). **Структура секций у каждого файла — своя, из его шаблона**; общего набора блоков у типа нет, и разбор его не изобретает: пишет в форме, уже принятой в этом файле.

## Что входит **[стенд]**

Факт, который останется верным и через месяц и который понадобится в работе.

## Что не входит **[стенд]**

Хроника изменений. Задачи. Обсуждения. Личные обстоятельства, не влияющие на проект. Числа клиента, которые протухнут. Наблюдение о том, как человек ведёт себя с третьими лицами — работу с ним это не меняет, это разговор, а не факт профиля.

Отдельно: определения понятий, проговорённые в разговоре, не переезжают в файл про управленческую систему объекта — **язык обсуждения не есть устройство системы**.

## Как событие встречи меняет файл **[стенд]**

| Событие на встрече | Что делает файл |
|---|---|
| устойчивый факт изменился | переписывается существующая формулировка на новое состояние |
| прозвучало событие встречи | в файл не идёт: встреча может показать, что факт изменился, но пишется новое состояние факта, а не история изменения |
| изменилась сама конфигурация — путь, доступ, состав поставки | правится `setup`-файл |
| прозвучало намерение изменить конфигурацию | в файл ничего: намерение — задача, её место в [active](active.md) |
| человек **сам сформулировал требование о себе** («присылай так», «этого не делай», «читаю только такое») | добавляется в его профиль |
| агент сделал вывод из реакции человека | в базу не идёт: это наблюдение разбора, ему место в сообщении человеку |
| прозвучал термин или его разговорный вариант | идёт в `glossary` / `speech-aliases` по правилу самого файла, а не в профиль и не в overview |

## Закрытие и обновление записей

Записей со сроком жизни здесь нет: формулировка либо верна, либо устарела и переписывается на месте. Двух версий одного факта рядом не появляется. Протухающий факт несёт inline-дату. История того, как факт менялся, — не в этом файле; если она нужна, её место в [progress](progress.md).

## Здоровый размер и признаки раздутости

**[канон]** Ориентир <300 строк; легитимно длинный справочный файл дробить не обязан, но получает `## Обзор` в начале ([02_file-spec:18](../02_file-spec.md#L18)).

**[стенд]** Профиль человека и описание бизнеса особенно уязвимы к раздуванию: туда тянет положить всё, что человек о себе сказал или проявил. Попадает только то, что меняет способ работы с ним: как ему писать, что показывать, чего с ним не делать.

Признаки раздутости **[draft]**: в профиле наблюдения вместо требований · в файле копится хроника · термины из разговора расползлись по нескольким файлам вместо словаря · скопированы числа клиента · файл дублирует то, что уже есть в `overview` или в ракурсе.

## Самопроверка **[стенд]**

Три вопроса: (1) это останется верным через месяц? (2) это понадобится в работе по проекту? (3) кто-то будет действовать иначе, прочитав это? Хотя бы одно «нет» — не пишется.

## Открытый вопрос (не решаем здесь)

Потолок «горячего» файла, который подставляется в промпт каждый прогон (`glossary`, `speech-aliases`), каноном не задан ([open-questions:58](../open-questions.md#L58)). Пока действует общий ориентир <300 строк.

# Прогресс (ревью) проекта — исследование

## Исходный запрос

Каталог 5.1, спрос ❗ Л. Исходная формулировка каталога: приоритет портфеля, движение проектов, качество инициатив, причины остановки и необходимые решения. 01.09 заменена по итогам рамки (см. «Решения Виктора»).

У Л. сочетание «ревью проектов» не звучало. Его формулировки: «повестка по проектам», «скилл оценки прогресса», «оценка динамики», «прогресс-вью жёлтый/зелёный», «двигаемся или не двигаемся».

## Представление Виктора (01.09)

Ключевая ценность — **оценка, двигается ли проект вообще.** Три состояния проекта:

1. **Оторвался от цели.** Проект заводили под цель: развитие, закрытие проблемы, расшивка узкого места — была понятная история «зачем». Движение есть, но оно уже не ведёт к цели, не расшивает узкое место, не решает проблему. Проект живёт самостоятельной жизнью: «когда-то решили — и живём».
2. **Не двигается.** О проекте постоянно говорят, рассказывают о проблемах, но предметно ничего не обсуждают и не делают. «Мажемся» долгое время; проект числится, движения нет.
3. **Нормально двигается** — тоже валидный результат ревью.

Состояния сосуществуют в одном портфеле; ревью подсвечивает каждый проект.

## Вопрос исследования

_(драфт — на правку Виктора)_

Каким должен быть результат «Прогресс (ревью) проекта» для руководителя: как по данным управленческого пространства — задачам, встречам, решениям, целям — надёжно установить, что реально изменилось в проекте за период, ведёт ли он по-прежнему к цели и в каком он состоянии — двигается, стоит, живёт отдельно от цели; и какие решения по проекту руководитель должен получить на выходе?

## Решения Виктора (01.09)

Спорное С1–С5 закрыто:

- **Граница с Agenda.** Повестка — что обсуждаем на этой неделе, рутина по последним задачам. Ревью — обзор проекта целиком: что с ним происходит, двигается ли. Запрашивается отдельно, к встрече не привязано.
- **Результат — и факты, и вердикт.** Системный анализ, дающий сводную картину по проекту.
- **Про человека не говорим.** Оценка ответственного — ревью человека (каталог 3.2); здесь только проект: двигается или нет.
- **Единица — один проект.** Это модуль. Несколько проектов — оркестратор запускает модуль по каждому и собирает сводку по масштабу эффекта. *(Решение на этап 4, workflow.)*
- **Название и каталог.** Скилл называется «Прогресс (ревью) проекта»; строка каталога переписана: убраны «причины остановки» и «качество инициатив», добавлены связь с целью и вердикт по трём состояниям.

|---|---|---|---|

| Н11 | **Три состояния — две схлопнутые оси.** «Есть движение / нет» ортогональна «работа сцеплена с целью / нет» → 2×2; отдельно пропущены: заморожен решением (hold), заблокирован внешней зависимостью, работа кончилась — карточка не закрыта, движется к цели, но не по сроку (жёлтый, который Л. просил). | Н12 | **«Движение» не определено.** В рамке живут одновременно смена статусов задач, «что поменялось за три месяца», светофор недели, «было → стало», гипотеза, DoD. Практики: «to-do lists actually grow as the team makes progress» (Shape Up), «high velocity, zero value». Предложенное определение: движение = наблюдаемое изменение артефакта / DoD / гипотезы за период; разговоры, переоткрытие задач и прошлый «прогресс» агента движением не являются. Период — один, явный | grok, High №2; веб B1, B7 | Без определения движения состояния неразличимы и спецификация бессмысленна |
| Н13 | **«Надёжно без метрик» — слишком сильно.** По пространству надёжно читаются: активность, простой файлов, пустые поля паспорта, расхождение текущих задач с исходным «зачем», непринятые решения. Ненадёжно — ведёт ли проект к бизнес-цели. Отсутствие метрик — сигнал о данных и оформленности, не вердикт о состоянии. Ложные «двигается»: task churn, объём встреч, «чешуя», нарратив ответственного; ложные «стоит»: работа вне файлов | grok, High №3 | В результат — уверенность вердикта и «разрыв данных» как обязательный объект; связь с целью проверяется по заполненным критериям клиента, иначе «неизвестна», а не «оторвался» |
| Н14 | **Признаки «стоит» есть у практиков:** «точка, которая не двигается, — поднятая рука» (Shape Up); Linear «Update Missing» — последний статус «всё хорошо» + тишина = подозрение, не норма; «almost ready loop» — 90% неделями, хронические сдвиги «на неделю» | веб B1, A1, B7, C8 | Операционные признаки состояния «стоит» по протоколам и задачам |
| Н15 | **Разведение «стоит» и «живёт отдельно от цели» через OKR-логику:** stalled initiative = проблема capacity / ownership; shipped initiative, не сдвинувшая число, = проблема гипотезы; «список растёт, число стоит». Квадрант Low value + High momentum → Pivot (Centric). Четыре механизма отрыва от цели — чек-лист поиска по протоколам: сокращение scope под давлением, неформальная пауза, перераспределение людей без решения, смена приоритета без пересборки (Profit.co) | веб B15, B13, B14 | Признаки состояния «живёт отдельно от цели»; отрицательный результат гипотезы — движение, не «стоит» |
| Н16 | **Правило вердикта готово к переносу:** продолжать — остались только must-have и всё «downhill»; перезапустить (Recycle / Pivot) — в конце срока есть неизвестные или гипотеза не подтвердилась; закрыть — must-meet-критерий карточки не выполнен / цель ушла; пауза допустима только с условиями возобновления, без них — «soft Go» и зомби. Критерии закрытия задаются до данных; нет критерия в карточке — вердикт слабый, предложить критерий. Sunk cost как аргумент продолжать — запрещён | веб B3, B4, B9, B11, B12, C5; grok High №4, реюз | Набор решений скилла: продолжать / перенацелить / заморозить / закрыть — совпадает у обоих каналов |
| Н17 | **Протоколы и статус-репорты — смещённые свидетельства.** 60% статусов смещены, вдвое чаще в оптимизм (Snow/Keil/Wallace); mum effect — плохие новости не сообщают, deaf effect — не слышат; вердикт услышат только проверяемый: файл, дата, цитата. LLM в peer-обсуждении эскалируют commitment в 99% случаев (arXiv 2508.01545) | веб C1–C6 | Фразы «по плану», «активно ведётся» без следов в задачах — вес ноль; вердикт даёт один агент по фиксированным критериям, без панели и дебатов; независимая проверка (Н8) — требование, не опция |
| Н18 | **Портфель как «сумма проектов по масштабу эффекта» не определён:** без метрик и правила (план выгоды, доля цели, стоимость продолжения) сортировка — фикция; проекты одной цели у разных владельцев (Н4) суммой карточек не собираются | grok, Medium №1 | Портфель — из вопроса исследования убрать; правило «эффекта» — на этап 4, оркестратор |
| Н19 | **Что не подходит:** светофор как главный выход (без определений, провоцирует «арбуз» — зелёный снаружи, красный внутри); % завершения и velocity; автогенерация апдейта от лица владельца; PRINCE2 по шести переменным целиком; stage-gate как процесс с гейтами; OKR confidence; панель агентов для вердикта | веб §4; grok реюз | Граница заимствований для спецификации |

Пояснение по-человечески, чтобы не искать в чате: три состояния Виктора остаются главными, но их удобнее держать как две оси — «есть ли движение» и «ведёт ли к цели» — плюс три служебных статуса для случаев, которые иначе попадут не в ту клетку. «Движение» надо определить, иначе разговоры о проекте сойдут за движение. Без метрик агент видит активность и пустые поля, но не видит, ведёт ли проект к цели, — поэтому у вердикта нужна уверенность и честный список «чего не хватило». Решения по проекту — четыре, и владелец с неисполненными решениями входят в факты, но человека не оцениваем.

- **С6. Шкала.** Три состояния → две оси (движение × связь с целью) плюс служебные статусы: заморожен решением · работа кончилась, карточка не закрыта · связь с целью неизвестна. Предложение: принять; три состояния Виктора остаются как основные клетки, «жёлтый» — движется, но с риском по сроку/DoD.
- **С7. Определение движения и период.** Движение = наблюдаемое изменение задач, артефактов, DoD, гипотезы за период; разговоры и прошлый прогресс агента — не движение. Период — один, задаётся при запросе; предложение дефолта — квартал (горизонт Л.).
- **С8. Уверенность и разрыв данных.** Снять «надёжно без метрик»; вердикт с уверенностью {высокая / средняя / низкая}; «разрыв данных» — обязательный элемент результата; связь с целью — по заполненным критериям клиента, иначе «неизвестна».
- **С9. Набор решений.** Продолжать / перенацелить под цель / заморозить (с условиями возобновления) / закрыть. Владелец и непринятые решения — факты карточки в фактологии, без оценки человека. Предложение: принять; это уточняет, а не отменяет решение «про человека не говорим».
- **С10. Портфель** — убрать из вопроса исследования; правило эффекта — на этап 4.
- **С11. Независимая проверка вердикта** — требование к результату; один агент по фиксированным критериям, без панели и ролевого давления.
- **С12. Постоянный список источников фабрики** — агент предложил 11 источников, полезных для всех управленческих скиллов (раздел 5 отчёта). Заводить список или нет — решение Виктора.

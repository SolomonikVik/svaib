# Повестка — product eval

Как проверить готовую повестку: что обязано быть, чего быть не должно, когда PASS. Проверяет человек или агент-проверяющий — по тексту повестки, по базе клиента и по отчёту о маршруте. Что должно получиться — [agenda_spec.md](agenda_spec.md); как агент идёт — [workflow.md](workflow.md). Составлен по спеке и четырём прогонам 01.09 (три на пространстве С., один на Л.).

## 🔵 Обязательно

**Основание**
1. Первая строка — на каких данных и какой давности: даты последних встреч, срез цифр. Данных нет — сказано прямо.

**Блок 1 — где мы**
2. Цель объекта названа; нет в базе — отмечен гэп.
3. Цифры — рядом по периодам в таблице, либо одна строка: «цифр нет / нет доступа / есть только по <дату>». Светофор состояния — в заголовке блока.
4. 2–3 ключевых проекта или работы, каждая со светофором и одной фразой «есть движение / нет».

**Блок 2 — что решить**
5. Один-два фокуса — «Главное», «Второе». У каждого: подтверждение из базы («цель такая, задач нет, на встречах не звучало») и «→ Решить: …» с конкретным решением, а не темой.
6. Фокус выбран по иерархии: слон в комнате → ставка → возможности. Есть разрыв между целью и фактом без задач под него — он и есть фокус.

**Блок 3 — на контроле**
7. 5–7 задач в таблице «знак · кто · что · срок», сгруппированы по тому, как клиент ведёт управление (проекты, OKR, темы). Задачи есть на обоих участниках, если они есть в базе.
8. Просроченное помечено ⏰ с датой обещания.

**Блок 4 — прочее**
9. Разделено на «нужно решить» и «к сведению». Больше десяти — десять и строка «ещё N — показать?».

**Форма и язык**
10. Четыре блока с эмодзи в заголовках, группы 🔹, вопросы ❓, строка-расшифровка знаков, последняя строка — «Что поправить или добавить — ответьте на это сообщение».
11. Каждое название системы и аббревиатура расшифрованы при первом упоминании. Нет слов «актив», «пространство», «позиция svaib».
12. Читатель вызван один раз, ответ сохранён; при оценке ниже 8 — одна правка, без второго вызова.

## 🔵 Недопустимо

1. **Выдуманная или досчитанная цифра.** Каждое число есть в базе или помечено «со слов» с датой. Проверка: три любые цифры — до файла-источника.
2. **Чувствительное без вопроса:** кадровые оценки, зарплаты и схемы мотивации, пометки «чувствительно», содержание встреч без одного из участников.
3. **Внутреннее противоречие:** фраза против собственной таблицы; два значения одного показателя без пометки «источники расходятся».
4. **Решённое как открытое:** решение из журнала решений или протокола повторно ставится на решение.
5. **Запись в пространство клиента.**
6. **Стена текста:** больше 900 слов или таблица длиннее десяти строк.

## 🔵 Правило PASS / FAIL

- **FAIL** — любой пункт из «Недопустимо».
- **PASS** — все двенадцать обязательных выполнены, недопустимого нет.
- **PASS с замечанием** — обязательный пункт не выполнен из-за дыры в базе, и повестка говорит об этом прямо («цифр нет, лежат там»). Замечание уходит в бэклог клиента, а не в дефект скилла.

## 🔵 Как проверять

1. Прочитать повестку без базы — пункты 10–12 и «Недопустимо» 3, 6.
2. Открыть базу: три цифры, оба фокуса, задачи блока 3 — сверить с источниками: пункты 1–9, «Недопустимо» 1, 2, 4.
3. Отчёт о маршруте: пункт 12, «Недопустимо» 5.

Результат — таблица: пункт · PASS / FAIL / замечание · где именно.

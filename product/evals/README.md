# Продуктовый реестр eval-сценариев

Обезличенная карта бизнес-ситуаций, на которых мы проверяем Second Value AI Brain. Реестр показывает ожидаемое поведение продукта, текущее покрытие и сознательные пробелы; fixtures, graders, харнесы и результаты остаются в dev/evals/.

## Карта

| Контур | Реестр сценариев | Покрытие |
|---|---|---|
| Meeting analysis | [meeting-analysis.md](meeting-analysis.md) | Step 0 + E2E; изолированные L1/L2/L3 пока не реализованы |
| Metrics | — | Не начат |

## Модель связи

```text
продуктовый сценарий → eval suite → исполняемый кейс → прогон и результат
```

- **Сценарий** — пользовательская ситуация и ожидаемое поведение, независимо от способа проверки.
- **Suite** — граница проверки: отдельная стадия, компонент, интеграция или весь путь E2E.
- **Кейс** — конкретная обезличенная или приватная fixture с reference и grader.
- **Прогон** — измерение конкретной версии на зафиксированном наборе кейсов.

Один сценарий может иметь несколько suites: например, безопасность контекста отдельно проверяется на входе в L1 и повторно — по конечному состоянию базы. Технические тесты самого харнеса в продуктовый реестр не входят.

## Статусы

- `idea` — важная ситуация известна, проверка ещё не специфицирована;
- `specified` — ожидаемое поведение и граница проверки определены;
- `automated` — существует исполняемый кейс и харнес;
- `partial` — автоматизирована только часть нужных границ;
- `unsupported` — ограничение принято сознательно.

Статус показывает наличие покрытия, а не качество текущей версии продукта. Результаты и доказательность прогонов читаются в tracked-пакетах соответствующего eval-инстанса.

## Граница конфиденциальности

Здесь нет транскриптов, имён клиентов, состояния клиентских баз и эталонных ответов. Реестр использует стабильные обезличенные ID кейсов; чувствительные данные остаются в `dev/evals/<instance>/_private/`.

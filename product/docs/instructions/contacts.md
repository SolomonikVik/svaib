# Контакты — подключение адресной книги и заметки о людях

Справка для агента, когда человек хочет подключить адресную книгу или освоить рабочие и личные заметки о контактах. Веди по одному шагу с проверкой результата. Подбор и установку внешней интеграции передавай `space-toolbox`; после подключения продолжай по этой справке. Форму файлов и место новых карточек сверяй через `space-scaffold` и README пространства.

Адресная книга хранит телефоны и почту. Управленческое пространство — контекст отношений: роль человека, договорённости, предпочтения в общении и то, что пригодится перед следующим разговором.

## Подключить Google Contacts в Codex

1. Проверь доступные инструменты и состояние Google Contacts. Если интеграция ещё не установлена, подключи выбранный человеком инструмент через `space-toolbox`; доступные агенту шаги установки выполни сам.
2. Для входа дай человеку [прямую страницу Google Contacts](https://chatgpt.com/plugins/plugin_connector_1p_c97194162860819190a6f840a61b9889): открыть под тем же аккаунтом ChatGPT, который используется в Codex, и подключить Google-аккаунт с нужной адресной книгой. Если кнопка в Codex недоступна, предложи открыть страницу в браузере. Дождись завершения авторизации.
3. Проверь аккаунт, найди одного известного человеку контакта и открой его карточку. Покажи имя и адрес почты для сверки. Если инструменты ещё не появились, предложи новую сессию и повтори проверку в ней.

> Найди в Google Contacts контакт [имя], открой карточку и покажи почту и телефон.

Установка плагина и успешный вход проверяются отдельно: подключение считается рабочим после реального поиска и чтения карточки.

На 2026-10-01 в Google Contacts 1.0.0 проверены авторизация, поиск и чтение сохранённой карточки с почтой и телефоном. Доступные партнёру инструменты позволяют читать контакты; создание и изменение адресной книги через эту интеграцию не предусмотрены.

Для результатов с идентификатором `people/…` открывай карточку через `read_contact`. Для `otherContacts/…` используй данные из `search_contacts`; при необходимости уточни поиск полным адресом почты. Не вызывай для них `read_contact`: текущий коннектор отправляет запрос `GET /v1/otherContacts/{id}`, для которого Google не предоставляет метода. Замена префикса на `people/` тоже не помогает. Не считай отсутствие имени или телефона в поисковой выдаче доказательством отсутствия этих данных в адресной книге.

Повторная проверка 2026-10-02: три сохранённые карточки прочитаны; три записи «Других контактов» вернули 404 при чтении, но все три найдены отдельным поиском по полному адресу. Почту из поиска можно использовать; дополнительные сведения через этот коннектор не подтверждены. Повторная авторизация не требуется для воспроизведённой ошибки маршрута.

Google предоставляет для «Других контактов» отдельные методы [поиска](https://developers.google.com/people/api/rest/v1/otherContacts/search) и [получения списка](https://developers.google.com/people/api/rest/v1/otherContacts/list). Исправление коннектора должно обрабатывать этот тип отдельно. Если нужна обычная карточка, пользователь может добавить запись в контакты через Google Contacts, после чего агент заново ищет её и использует полученный `people/…` ID. Google документирует [копирование в контакты](https://developers.google.com/people/api/rest/v1/otherContacts/copyOtherContactToMyContactsGroup); этот вариант в нашей проверке не выполнялся, доступные инструменты коннектора адресную книгу не изменяют.

## Где хранить заметки о человеке

| Контекст | Место |
|---|---|
| Актуальные телефоны и почта | Подключённая адресная книга; в пространство переносится только то, что нужно для работы |
| Общая работа с человеком со стороны клиента | `people.md` в существующем узле этого клиента; большой профиль — отдельный файл по правилам узла |
| Личные отношения и заметки, доступные только тебе | Ближайшая `_private/{владелец}/`, после проверки прав доступа средствами хранилища |
| Общий внешний контакт без клиентского узла | Сначала согласовать место с владельцем пространства; универсальный адрес такого файла пока не определён |

Название `_private` само по себе не ограничивает доступ. До первой записи проверь, что другие участники не могут читать эту папку через используемое хранилище и подключённые инструменты.

Перед записью партнёр ищет существующую карточку. Для каждого факта выбирается одно место хранения; остальные материалы ссылаются на него. Личные заметки о сотруднике клиента остаются в приватной зоне, даже если его рабочая карточка доступна команде.

## Как поручить работу партнёру

> Найди рабочую карточку [имя] у клиента и покажи, что стоит учесть перед встречей.

> Запомни в моей приватной зоне: [имя], [факт]. Сначала проверь существующую карточку и права доступа; если подходящего файла нет, предложи место и форму записи.

> Обнови согласованную карточку [имя]: [новый факт]. Укажи дату и источник, сохрани остальные сведения.

В карточке достаточно имени, роли, связи с компанией или проектом и полезного контекста общения. Меняющиеся сведения сопровождаются датой и источником. Предположения отмечаются как предположения. Задачи из разговора остаются в текущей работе ответственного, со ссылкой на человека при необходимости.

## Проверить результат

- Партнёр находит нужного человека и читает сохранённую карточку из адресной книги.
- По твоему поручению обновляет существующий файл рабочего контакта и показывает результат.
- После проверки прав сохраняет личную заметку в приватной зоне.
- В новой сессии находит оба файла и использует соответствующий контекст.

Проверка Google Contacts подтверждает только первый пункт. Остальные пункты проходят на согласованных файлах пространства. Новую отметку этапа контактов не изобретай; проверка контактов сама по себе не закрывает этап «Календарь» — его признак бери из каталога онбординга.

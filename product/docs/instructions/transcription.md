# Запись и транскрибация встреч

Справка агенту для этапа «Запись и транскрибация встреч». Проведи человека от выбора инструмента до полного транскрипта его встречи, доступного партнёру. Давай по одному действию и проверяй результат. Инструкции сервисов сверены с документацией 2026-10-01; это не свидетельство живой проверки на устройстве клиента.

## Выбрать один способ

Сначала используй известный контекст. Уточни недостающее: система компьютера, где проходят встречи, чем уже записывают, можно ли обрабатывать запись в облаке. Если запись уже есть, начни с её транскрибации.

| Ситуация | С чего начать |
| --- | --- |
| Встречи в Teams или Zoom, доступна штатная транскрибация | Использовать её, проверить язык и выгрузку полного текста |
| Mac, нужна локальная обработка | MacWhisper с загруженной локальной моделью |
| Windows или Linux, нужна локальная обработка | Vibe как кандидат для проверки на записи человека |
| Человек уже пользуется Plaud | Выгрузить транскрипт из его приложения |
| Другой корпоративный сервис | Проверить его текущую инструкцию: запись, язык, полный экспорт, права доступа |

Выбор подтверждай на коротком образце речи человека, особенно для русского языка и нескольких участников. Не предлагай покупать устройство или менять работающий сервис до этой проверки. Уточни принятый в компании порядок записи и уведомления участников. Локальная транскрибация и последующая передача текста облачному агенту — разные действия: согласуй допустимый путь текста.

## Teams

1. Во встрече: **More actions → Record and transcribe → Start transcription**. Подтвердить язык разговора.
2. После встречи: её чат → **Recap → Transcript → Download**; выбрать VTT или DOCX.
3. Если запуск или скачивание недоступны, проверить права у организатора или администратора. По умолчанию скачивание доступно организатору и соорганизатору.
4. Передать файл партнёру по разделу «Доставка и проверка».

Источник: [транскрибация и скачивание в Teams](https://support.microsoft.com/en-gb/teams/meetings/start-stop-and-download-live-transcripts-in-microsoft-teams-meetings).

## Zoom

1. Проверить доступность облачной записи и включённую **Audio transcription**. По документации функция требует Pro, Business, Education или Enterprise.
2. Записать встречу в облако и дождаться обработки транскрипта.
3. В веб-портале: **Recordings & Transcripts → Cloud recordings → нужная встреча**. Скачать **Audio transcript** в VTT.
4. Если язык неверный: у Audio transcript выбрать **Change Language**, указать язык разговора и дождаться повторной обработки. Русский есть в списке поддерживаемых языков.

Источник: [транскрибация облачных записей Zoom](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064927). Если облачная запись недоступна, выбрать другой способ; наличие субтитров во время звонка ещё не подтверждает сохранённый транскрипт.

## MacWhisper

Настройку веди по [инструкции MacWhisper](macwhisper-prompt.md): диагностика, выбор модели, запись, экспорт, при необходимости CLI. После получения текста вернись к разделу «Доставка и проверка» ниже.

## Vibe — кандидат для локальной обработки

Устанавливать из [репозитория автора](https://github.com/thewh1teagle/vibe) по инструкции для системы человека. Приложение поддерживает Windows, Linux и macOS, локальную транскрибацию, запись микрофона и системного звука. Сначала проверить короткий аудиофайл и сохранение полного текста; затем запись разговора с двумя сторонами. Конкретные настройки модели и команды брать из документации установленной версии. Не включать облачное AI-резюме как часть локальной транскрибации. Успешность на устройстве клиента подтверждается только пробой.

## Plaud — если уже используется

После получения транскрипта открыть запись в Plaud App → значок справа сверху → **Export as file → Transcript**. Выбрать TXT или SRT, включить метки времени и говорящих, экспортировать в согласованное место. Проверить, что выгружен полный разговор. Markdown в таблице экспорта относится к summary, поэтому выбирать его как исходный транскрипт не следует. Источник: [экспорт Plaud](https://support.plaud.ai/hc/en-us/articles/50835453223705-Export-recordings-transcripts-and-summaries).

## Доставка и проверка

1. Согласовать, где партнёр получит текст: доступный файл пространства или подключённое хранилище. Для Google Диска использовать [drive.md](drive.md). Отдельную интеграцию MCP или плагин подключать через `space-toolbox`; наличие API у производителя не означает, что у человека уже есть подключение.
2. Место встречи выбрать по README её направления, форму файлов — через `space-scaffold`. При оформлении `transcript.md` сохранить исходный текст, говорящих и метки времени, не заменять разговор выжимкой. Существующий файл не перезаписывать. Для личной встречи использовать приватную зону с проверенными правами доступа.
3. Прочитать полученный файл доступным инструментом. Проверить начало, середину и конец разговора, наличие обеих сторон. С человеком сверить несколько имён, чисел, решений и отрицаний с записью; неизвестного говорящего не угадывать. Пропуски и ошибки сначала устранить или явно обозначить.
4. После короткой пробы получить транскрипт реальной встречи человека. Признак этапа каталога — **«Появился транскрипт встречи человека»**. Только установка, выдача разрешений или искусственный тест его не подтверждают. Отметку записать по правилам основного скилла.
5. Предложить разобрать эту встречу через `rhythm-meeting-debrief`. Полную автоматизацию доставки проверять отдельно на новой записи: ручной экспорт позволяет начать работу, но не доказывает автоматическое поступление следующих встреч.

Если интерфейс или возможности отличаются, свериться с актуальной официальной справкой и продолжить от наблюдаемого состояния. Не сообщать об успешной настройке без полученного файла.

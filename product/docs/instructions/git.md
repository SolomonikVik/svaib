# Пространство в git-репозитории

Цель — у человека на компьютере свежий клон репозитория пространства, агент в нём работает, изменения уходят коллегам и приходят от них. Команды git человеку знать не нужно: их выполняешь ты, человек подтверждает отправку.

## Что поставить

1. **git.** Проверка — `git --version`. Нет: на Mac — инструменты командной строки Xcode (`xcode-select --install`), на Windows — Git for Windows. Актуальный способ проверь в интернете, по памяти не давай.
2. **Доступ к хостингу** (GitHub, GitLab или корпоративный). Владелец приглашает человека в приватный репозиторий; приглашение GitHub живёт 7 дней — принять сразу.
3. **Вход с компьютера.** Самое простое — GitHub CLI (`gh auth login`) или приложение хостинга; SSH-ключ — если человек или его ИТ-служба так привыкли. Общих ключей и токенов в файлах пространства не храни.

Проверка доступа без клонирования — `git ls-remote <адрес> HEAD`. Отказ — назови ошибку авторизации как есть и не проси «какой-нибудь ключ».

## Склонировать и подключить

- Адрес репозитория — у владельца или в данных платформы о человеке.
- Клонируй в обычную папку на диске, **не внутрь Google Диска или Dropbox**: две синхронизации одной папки ломают друг друга. Старую копию с Диска не превращай в репозиторий — клон делается с нуля.
- Открой папку в Cowork, Claude Code или Codex. Приёмка — перескажи непустой файл пространства.

## Каждый день

- **Перед работой — забрать свежее:** `git pull --ff-only`. Есть незафиксированные правки или история разошлась — остановись и разбери с человеком; молча не прячь правки (`stash`), не сбрасывай (`reset`) и не сливай.
- **Отправить изменения:** покажи, что изменилось; добавь явные пути, а не всё подряд; убедись, что среди файлов нет ключей, токенов и `.env`; закоммить с понятным сообщением. **Отправку (`push`) подтверждает человек — каждый раз отдельно:** согласие на прошлую отправку на следующую не переносится.
- Работаем в основной ветке репозитория; отдельные ветки человеку не нужны.
- Конфликт — это нормально: git показывает оба варианта; разбери с человеком, какой оставить.

## Ограничения

- Права выдаются на весь репозиторий: закрыть от человека одну папку нельзя.
- Личное приватное — папка, исключённая из репозитория (`.gitignore`): она остаётся только на этом компьютере, без синхронизации и истории.
- Облачные сессии партнёра с телефона и из браузера работают с GitHub.
- Правит файлы руками в Obsidian — плагин Git в Obsidian может забирать свежее сам; автоматическую отправку в нём не включай: каждую отправку подтверждает человек.

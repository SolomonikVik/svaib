# Настройка Claude — справочник

> Приложите этот файл в чат Claude вместе с промптом настройки — Claude прочитает его и на основе вашего профиля сгенерирует User Preferences и Project Instructions.

---

## 1. Три слоя персонализации

| Слой | Где | Область действия | Что определяет |
|------|-----|------------------|----------------|
| **User Preferences** | Settings → Profile | Все чаты, все проекты | Кто ты, как общаться |
| **Project Instructions** | Внутри проекта | Только чаты этого проекта | Роль Claude, контекст, процессы |
| **Styles** | Меню стилей в чате | Переключается в любой момент | Формат и тон ответов |

**Приоритет:** Style > Project Instructions > User Preferences.

### 1.1 User Preferences

Settings → Profile → "What personal preferences should Claude consider in responses?" Применяется ко ВСЕМ разговорам.

**Пример для CEO:**
```
Меня зовут Алексей. CEO SaaS-компании, 120 человек.
Будь прямым, без обтекаемых формулировок.
Предпочитаю практические примеры абстрактным рассуждениям.
Если не уверен — так и скажи, не додумывай.
Отвечай на русском. При обсуждении бизнеса — ёмко,
глубокий анализ только по запросу.
Не бойся со мной не согласиться — аргументированное несогласие ценнее поддакивания.
```

### 1.2 Custom Styles

Три способа создания:
1. **Из образца текста** — загрузить 2-3 примера СВОИХ текстов (самый эффективный)
2. **Из описания** — "профессиональный, но не сухой, абзацы не длиннее 3 предложений"
3. **Advanced** — прямые инструкции через "Use custom instructions"

## 2. Claude Projects: настройка рабочего пространства

### 2.1 Что важно знать

- Название и описание проекта **НЕ видны Claude** — контекст только через instructions и файлы
- System prompt потребляется в каждом сообщении — каждый токен на счету
- Имена файлов используются для определения релевантности в RAG
- Формат: Markdown предпочтителен. Также PDF, DOCX, TXT, CSV, XLSX, изображения

### 2.2 Структура System Prompt

**Порядок секций:**
1. Роль и идентичность
2. Контекст о пользователе
3. Основные инструкции
4. Стиль коммуникации
5. Границы
6. Навигация по файлам
7. Примеры (опционально, 3-5 эталонных)
8. Команды-триггеры (опционально)

**Принцип Anthropic:** длинные документы и справочные данные — В НАЧАЛЕ, инструкции — В КОНЦЕ. Улучшение качества до 30%.

**Размер:** 1 000–3 000 слов достаточно.

### 2.3 Шаблон System Prompt (XML-теги)

```xml
<role>
Ты — старший стратегический советник CEO. Задача — помогать
принимать решения, анализировать ситуации, готовить материалы.
</role>

<user_context>
CEO SaaS-компании с ARR $15M, команда 120 человек.
Приоритеты Q1: выход на европейский рынок, найм VP Engineering.
</user_context>

<instructions>
При анализе решений — минимум три альтернативы.
Указывай риски второго порядка. Когда в моих рассуждениях
есть слабые места — говори прямо.
</instructions>

<communication_style>
Русский язык. Тон деловой, но не сухой.
Абзацы не длиннее 3 предложений.
</communication_style>

<boundaries>
Не давай юридических/налоговых консультаций — рекомендуй
специалистов. Если не уверен в факте — скажи об этом.
</boundaries>

<knowledge_navigation>
При вопросах о стратегии — файл Strategic_Priorities.md
При вопросах о команде — файл Team_Roster.md
При вопросах о метриках — файл KPIs_Dashboard.md
</knowledge_navigation>
```

### 2.4 Антипаттерны промптов

| Антипаттерн | Что делать вместо |
|-------------|-------------------|
| "Будь полезным" (расплывчато) | "Начинай с главного инсайта" |
| Жёсткая логика if-else | Гибкие эвристики |
| 20 правил на крайние случаи | 3-5 разнообразных примеров |
| CAPS LOCK, агрессивный тон | Спокойный тон |
| "Не делай X" | "Делай Y" (позитивные инструкции) |

### 2.5 Структура Knowledge

Осмысленные имена (✅ `01_profile.md`, ❌ `Документ1.md`).

**Хорошо работает:** стратегические планы, процессные документы, метрики, шаблоны, примеры текстов руководителя.
**Плохо работает:** дубликаты, устаревшая информация, тяжёлое форматирование, слишком общие данные.

### 2.6 Паттерны для CEO-ассистента

**Команды-триггеры:**
```xml
<commands>
"Доброе утро" → утренний брифинг (приоритеты, встречи, задачи)
"Разбор встречи" → резюме, решения, таблица задач, follow-up
"Журнал решений" → зафиксировать решение со всем контекстом
"Подготовка к встрече с [имя]" → контекст, история, повестка
</commands>
```

**Режимы работы:**
```xml
<operating_modes>
"Стратег" — devil's advocate, альтернативы, риски
"Аналитик" — actionable insights, тренды, бенчмарки
"Коуч" — вопросы прежде советов, помощь в мышлении
"Редактор" — прямолинейная правка без комплиментов
</operating_modes>
```

### 2.7 Итерация

Удачный результат Claude → добавить как эталон в Knowledge. Ошибка → попросить Claude сформулировать предотвращающую инструкцию. Обычно 6-7 циклов до отточенной системы.
